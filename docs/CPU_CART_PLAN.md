## 〇、v1.1 修订要点（读完官方资料后）

从 `D:\yingxu_ziyuan` 的原理图与例程里确认了一批**现成但完全闲置**的硬件，
方案从"纯 BRAM 单机"升级为"总线化小主机"：

| 器件 | 位置/总线 | 厂商参考 RTL（本板验证过） | 在方案中的角色 |
|---|---|---|---|
| **IS61WV51216** 512K×16 异步 SRAM（1MB） | 核心板 BANK3，18A+16D+CE/WE/OE/LB/UB | `AC201_AL_SRAM` 例程 | v2：卡带缓存（开机预载 4 张、拨码秒切）/ 银行化内存 / 软件帧缓冲 |
| **24LC64** 8KB EEPROM | 底板主 I2C（`i2c_sclk/sdat`） | `AC201_uart_to_eeprom` 例程 | **v1.5：最高分/存档**（断电不丢）——游戏机的灵魂特性 |
| **PCF8563 RTC**（带电池） | 同一 I2C 总线 | 同上例程 | v1.5：最高分时间戳 / 屏上真实时钟 |
| **WM8960 编解码**（耳机口+喇叭+麦克风） | I2S + 同一 I2C 总线 | v3 需重写初始化表（板载是 WM8960 而非官方板的 ES8388） | v3：掌机模式（无显示器也有声音） |
| 红外接收头 HS38B | 底板 `ir` 输入 | `src` 内 `ir_decode.v` | v3：遥控选卡带 / 红外手柄 |
| 8 位数码管（双 74595 三线制） | 底板 `seg7_*` | `src` 内 `HC595_Driver.v`+`HEX8.v` | v1.5：物理显示当前卡带号/分数 |
| SD 卡**写**通路 | SPI | `AC201_uart_sd_rw` 例程（本板验证过） | 备选：CPU 存档直接落 SD |

关键结论：**SRAM 控制器、I2C 主机、74595 驱动全部有本板验证过的现成 RTL**，
新增外围的工程风险大幅低于从零编写。SRAM 的 38 个引脚（BANK3）在引脚表
`AC201-EG4S20管脚信息表.xlsx` 与 SRAM 例程的 `io.adc` 中可直接取用
（注意：板测例程名"不含SD_SRAM_EEPROM"，其 IO.adc 没有这些脚，引脚从 SRAM 例程取）。

另两个事实修正：AC201 只有**一个** HDMI（指南里双 HDMI 是官方板 HX4S20C 的）；
底板音频编解码是 **WM8960**（ES8388 初始化表不适用）。

## 一、总览

```
                 ┌──────────── sys_clk 50 MHz 域 ────────────┐
 SD 卡 ──SPI──► 卡带加载器 ──► 程序RAM(1K×24, BRAM)           │
                    │            ▲                           │
                    │            │ 取指/执行                  │
                    └──► 数据RAM │ YX-8 CPU（单周期，~600 LUT）│
                                 │                           │
             按键(2FF同步) ◄──────┤ I/O 窗口 0xE0-0xFF        │
             帧计数/随机数 ◄──────┤                           │
             PSG 音效事件 ───────►│（复用现有 PSG，零新增）    │
                                 │                           │
                 sprite 桥（CDC，写请求跨到像素域）             │
                                 ▼                           │
                 ┌──── 像素域 73.33 MHz ─────────────────────┐│
                 │ 精灵引擎槽位表 ◄── 第四个写源（模式=卡带）  ││
                 └───────────────────────────────────────────┘│
                 └────────────────────────────────────────────┘
```

三个设计原则：
1. **CPU 完全活在 sys_clk 域**，与 SD/按键/PSG 天然同域；只有精灵表写入需要跨到像素域（写频次 ≤ 每帧几十次，电平握手足够，不做 FIFO）。
2. **程序在片上 BRAM 执行**（不取指于 SDRAM）——单周期、时序安全、加载即换卡带。
3. **对游戏程序暴露的只有 256 字节地址空间 + I/O 窗口**——平台 API 极小而完整，这也是"卡带格式"的核心。

## 二、YX-8 指令集（已冻结，2026-10-25）

### 2.1 机器模型

| 项 | 规格 | 说明 |
|---|---|---|
| 数据宽度 | 8 位 | 与"8-bit 主机"叙事一致 |
| 通用寄存器 | R0–R7 × 8 位 | X=R3 别名（仅变址寻址用） |
| PC | 16 位 | 程序 RAM 1K 字，实际用 10 位 |
| SP | 6 位 | 专用硬件栈 64×16（JSR/RTS），不占数据空间 |
| 标志 | Z / C / N | C：加减为无借位（dst≥src），移位为最后移出位 |
| 指令长度 | **定长 24 位** [op][A][B] | 取指单周期，译码极简 |
| 执行 | **单周期**（JMP/JSR 双字双周期） | 50 MHz → 一帧 83 万周期，游戏随便写 |

### 2.2 指令编码

**RR/立即数类**（A=目的寄存器，B=源寄存器或立即数）：

| 组 | 指令 | 标志 |
|---|---|---|
| 算术 | ADD/ADC/SUB/SBC/CMP | Z C N（**CMP 只改标志，绝不写回**） |
| 逻辑 | AND/OR/XOR | Z N |
| 移位 | SHL/SHR/ROL/ROR（移位量在 B，0-7；ROL/ROR 为 8 位循环） | Z C N |
| 传送 | MOV（RR）、MOVI/LDI（立即数） | MOV/LDI 只改 Z N |
| 杂项 | INC/DEC/NEG，CLC/SEC/NOP | 部分 |

**访存类**：`LDR/STR Ra,[addr]` 与 `LDR/STR Ra,[addr+X]`（变址）。

**控制流**：BEQ/BNE/BCS/BCC/BMI/BPL/BRA（单字，B=有符号±127 相对跳，目标=分支地址+1+offset）；
JMP/JSR（**双字**：本字 A=低 8 位，下一字 A=高 8 位）；RTS；**WFI**（休眠至下一帧 vblank——
游戏主循环的节拍器：`loop: …逻辑… WFI; BRA loop`）；HLT（预留调试）。

操作码空间 256，v1 用约 45 个；MUL（可用 DSP）、远寻址、断点为预留码位。

## 三、存储与 I/O 映射（v1.1.2 修正版，与模拟器/示例卡带一致）

```
0x00–0xBF  数据 RAM（192 字节，BRAM，复位清零/卡带 DATA 段预置）
0xC0–0xDF  【v2】SRAM 银行窗口：32 字节 × 页寄存器(0xF5) → 512K×16 的 8 位视图
           （v1 阶段此窗口映射为普通 BRAM，软件行为完全一致）
0xE0–0xE7  砖块位图 brick_mask[59:0]（8 字节；瓦片滚动硬件自动，无需寄存器）
0xE8–0xF0  精灵暂存 9 字节：en / xL / xH / yL / yH / w / h / colorL / colorH
           （坐标 11/10 位 → 各占 2 字节；颜色为 RGB565，硬件位复制展开 888）
0xF1       精灵提交：写入槽号 0-15 → 暂存 9 字节原子提交到该槽（经 CDC 桥）
0xF2  按键  bit0=key_0(左) bit1=key_1(右)；bit2-7 预留（v3 红外手柄。
           第三物理键 rst_n 即全局复位，不可作游戏键——原理图确认）
0xF3  帧计数  每 vblank +1，回绕
0xF4  随机数  LFSR 只读
0xF5  PSG 事件 写 0/1/2/3 = 撞砖/撞板/失败/通关（复用现有 PSG）
0xF6  系统    读：bit7=vblank，bit1-0=当前卡带号；写任意值=热重启请求
0xF7  保留
0xF8–0xF9 【v1.5】I2C 地址（EEPROM 16 位地址 / RTC 寄存器号）
0xFA      【v1.5】I2C 数据
0xFB      【v1.5】I2C 命令/状态：写 1=EEPROM 写 2=EEPROM 读 3=RTC 读；读 bit7=忙
0xFC      【v1.5】I2C 读数据
0xFD      【v1.5】I2C 读数据（RTC 用）
0xFE      计分条  写：屏下段条点亮的段数（0-8）
0xFF  保留
```

**槽位窗口化**：16 槽 × 9 字节若直接映射会吃掉 144 字节地址空间；"暂存 + 提交"
只占 10 字节且**提交即原子**（不会出现半新半旧的槽被渲染——硬件游戏
"y=0 更新拖尾影"的教训在 API 层面根治）。提交经 CDC 桥进像素域精灵表
（与清表扫描器/侵略者/打砖块四路 mux，模式字扩为 2 位：00=打砖块 01=侵略者 10=卡带）。

## 四、卡带格式 `.yxc`

| 偏移 | 字段 | 值/说明 |
|---|---|---|
| 0x00 | 魔数 | `"YXCA"`（4B） |
| 0x04 | 版本 | 1 |
| 0x05 | 标志 | bit0=含 DATA 段 |
| 0x06 | 入口点 | 16 位 LE（程序字地址） |
| 0x08 | CODE 长度 | 16 位 LE（24 位字数） |
| 0x0A | DATA 长度 | 16 位 LE（字节） |
| 0x0C | DATA 装载地址 | 8 位（数据段必须连续，从该地址平铺） |
| 0x10 | 标题 | 16 字节 ASCII（预留开机横幅，v2 显示） |
| 0x20 | CODE | 24 位字流（3 字节/字：op, A, B） |
| … | DATA | 按装载地址平铺的字节 |

SD 卡上按**连续 LBA**摆放（计划放在卡片末尾固定高地址区，避免照片增删移动 LBA）。
加载流程：SD 初始化 → 读头扇区校验魔数/长度（越界即失败报错）→ CODE 灌程序 RAM、
DATA 灌数据 RAM → 释放 CPU 复位 → 运行。**热换卡带**：写 0xF6 复位 → 回加载器。

## 五、微架构与实现

### 5.1 数据通路（单周期）

```
PC ──► 程序RAM(1K×24, 同步读) ──► 指令寄存输出
       ├── 操作码译码（组合）
       ├── 寄存器堆 8×8（LUTRAM，异步读 ×2 口）
       ├── 8 位 ALU（加减/逻辑/移位；CMP 只出标志）
       ├── 标志寄存器 Z/C/N
       ├── 地址合成（直寻址 / base+X）──► 数据RAM 与 I/O 窗口（写使能路由）
       └── 下一 PC（顺序+1 / 相对跳 / 双字第二拍 / WFI挂起）
```

关键时序：BRAM 同步输出(已寄存) → 译码+LUTRAM 读+ALU → 写回。约 8~10 级 LUT，
50 MHz（20ns）裕量充足；**不碰像素域，天然规避 P5 式布局陷阱的主要风险面**。

### 5.2 跨域桥（CPU → 精灵表）

```
50M 侧：0xE8-0xF0 暂存寄存器 + 0xF1 提交沿置 toggle（携带槽号）
像素侧：toggle 2FF 同步 → 一拍把 9 字节拼 67 位写入 spr_tab
```
每帧最多几十次提交，握手延迟 <0.1µs，无 FIFO。反向（帧计数/vblank）2FF 同步只读。

### 5.3 资源预算（对 12,279 空闲 LUT / 37 空闲 BRAM）

| 模块 | LUT | BRAM(9K) |
|---|---|---|
| YX-8 核心（寄存器堆/ALU/译码/PC/栈） | ~600 | 1（栈可 LUTRAM 化） |
| 数据 RAM 192×8 | ~20 | — |
| 程序 RAM 1K×24（可参数化 2K） | ~30 | 3–6 |
| 卡带加载器 FSM（复用 SD 探针通路） | ~250 | — |
| CDC 桥 + 模式 mux 扩展 | ~150 | — |
| **v1 小计** | **~1,100** | **4–7** |
| v1.5：I2C 主机（EEPROM+RTC）+ 数码管驱动 | ~190 | — |
| v2：SRAM 控制器（异步，50MHz 零等待） | ~150 | — |
| **全量小计** | **~1,450** | **4–7** |

占用后全片仍 ~44% LUT、<50% BRAM，DSP 继续为 0（音频域除外）。

### 5.4 引脚增量

| 组 | 数量 | 来源 |
|---|---|---|
| SRAM（v2） | 18 地址 + 16 数据 + CE/WE/OE/LB/UB = 38 | 核心板 BANK3，引脚从 SRAM 例程 io.adc / 引脚信息表 xlsx 取 |
| I2C（v1.5） | 2（i2c_sclk/sdat，已在顶层） | 现有端口，改赋值即可 |

## 九、演示脚本（答辩现场 3 分钟）

1. 上电 → 照片浏览器（30s，媒体能力）
2. SW6 → 打砖块 / 侵略者（30s，硬件 FSM 游戏）
3. SW6 再切 → **卡带模式：YX-8 运行汇编游戏**（60s，高潮：报出"这颗 CPU 是我们自己的指令集，游戏是队友用我们自己的汇编器写的"）
4. 打出高分 → **断电 → 重新上电 → 最高分还在**（30s，EEPROM 存档 + RTC 时间戳）
5. 热换卡带 / 拨码秒切另一款卡带游戏（30s）
6. 收尾：数码管显示卡带号，屏上 RTC 时钟 + 平台架构图（30s）

对照讲解词："打砖块是硬件状态机——每改一个玩法都要重新综合；卡带游戏是软件——
同一块板上改几行汇编重新打包就换了一个游戏。**这就是'可重构图形平台'的完成态。**"

**共生验证抓到的 RTL bug（编译器不可能发现，上板即挂）**：

1. **JSR 压栈判据用了 F2 拍的操作码**——双字指令第二字 op=0x00，`if(op==0x51)` 永假
   → JSR 从不压栈 → 首个 RTS 读到未初始化栈、全机 X 化。修复：译码拍锁存 `jsr_r`。
   （症状链：RTL 在 clearmask 的 RTS 处冻结，逐拍窗口探针抓到 sp=0/npc=X 现行）
2. 测试台复位期程序 RAM 预取与 pc 错位一拍（首指令执行 prom[1] 而非 prom[0]）。
3. 无写指令的轨迹 wv 字段两侧不对齐（对齐规范后零差异）。

**验证方法（答辩可讲）**：同一份 .yxc，模拟器（Python，指令级语义定义）与 RTL
（Icarus Verilog）各跑一遍，逐指令比对 17 元组全状态（PC/操作数/8 寄存器/3 标志/
写地址/写数据）——RTL 与"规格文档即模拟器"完全等价的数学证明。

# D7 + D6 统一交付

本文件为 D7 历史交付。D8 的视频握手、打砖块接线、渐变/logo 和最新构建说明
见 [D8 交付](D8_DELIVERY.md)；原 D7 证据保留。

构建分支：`feat/unified-menu-photo-video`。基于统一版 `0f92aac`，合并字模分支
`a1645d1` 的历史，包括 D6 `c25b9c5`；保留视频恢复补丁 `c218ed1`（原
`add9742` 的重放）、照片首读与 SD 初始化门禁。

## 最终行为

- 菜单用 `yingxu_menu_ui.v` 和原样引入的 `yingxu_cn_font.v` 按扫描坐标绘制。
  深蓝背景、6 px 黑框、黄色面板、文字坐标均按 [任务书](D7_MENU_UI.md)。
  页 0 五项，页 1 打砖块/飞机大战。切页只改文字，选择只改 slot 15 绿标。
- 菜单出现、切页、返回和视频坏头回退均不启动 BMP。菜单在 SD 初始化之前
  已可见；卡上菜单 BMP 不再用于菜单显示。照片仍保留原 BMP 路径和初始化门禁。
- 图片索引 0 保留作硬件菜单标识；照片前后翻页、轮播在 1..8 循环，避免
  轮播把硬件菜单当成照片。返回菜单取消照片淡入淡出事务，并重新准备下次照片加载。
- D6 的开机 0.5 秒屏蔽窗口与原 20 ms DIP 稳定确认共存。窗口内持续追踪
  引脚，但不发布变化。SW7 ON + key0 短按从模式/子菜单返回主菜单，保留
  2 秒长按兜底；返回时重新建立 DIP 基线，避免 SW7 操作延迟把菜单再次退出。
- 维修直通的视频失败保留 MISE/I1 等诊断，回退画面改成硬件菜单；显式返回
  后恢复交互菜单。视频 loader/arbiter/pipeline、SD reader、照片 player 与
  SDRAM 控制器的生产源码均与 `0f92aac` 相同。

任务书要求虚拟 `5F` 为硬件飞机大战，而旧实体 DIP 的 `5F` 是卡带。
为同时满足固定编码和维修兼容，仅 `menu_override=1 && menu_pattern=5F`
映射到 `game_sel2=1`；实体 `5F` 继续是卡带。打砖块用虚拟 `7F`、game_sel2=0。
确认子菜单游戏时实体 SW7 应为 OFF；SW7 ON + key0 按任务书返回主菜单。

菜单 WC 低位兼容原编码：主菜单 `008..00C`；子菜单 `018..019`，bit 4
表示 page。视频诊断仍优先使用既有 WC/MISE/I1 编码。

## 验证与图像

- `python3 tools/d7_menu_verify.py`：7 个完整活动帧，共 6,451,200 像素。
  对每像素的背景/面板/全部字模位、页间背景不变、选择时文字不变、实际精灵
  合成坐标和不遮挡文字均作断言。Yosys read/proc/opt/check 通过。
- `python3 tools/menu_mode_verify.py`：完整 25,000,000 周期开机窗口，包含
  长于 20 ms 的上电开关变化；随后实际顶层 5 条模式路径各做稳定/毛刺两组。
  检查五项/两项循环、关于占位、两个硬件游戏、视频真实所有权、音乐、照片、
  SW7+key0 返回、2 秒兜底、返回后超过 20 ms 仍保持菜单、实体维修直通，
  并持续断言菜单不发 BMP 启动。模式测试只预置开机/长按的已过时间与按键锁，
  独立开机测试和所有 20 ms 窗口运行真实计数。
- `python3 tools/d5_menu_verify.py`：保留菜单条生产过程的读取检查，验证
  五坐标、开机清表后恢复、退出清除、模式/故障返回和实体开关。用一帧视频
  夹具验证退场；不把 72 帧 PCM 预载耗时算进短流程超时窗口。
- `python3 tools/yxv_d3_verify.py --frames 2`：真实顶层视频/PCM/扫描零差异，
  48 kHz 比率通过，退出释放所有权。`--bad 1`：回退硬件菜单且不读 BMP，
  实际 UART 仍保留 `MISE=3992`、`ACC=200` 等故障证据。

精灵引擎原有行缓冲采用 RGB565，绿标写入颜色仍是 `00A651`，输出扩展为
`00A652`；其余菜单背景、面板、黑色文字直接走 RGB888。此量化行为未修改。

## 本地构建

在实际用于 TD 的统一分支检出目录执行：

```sh
git pull --ff-only
python tools/prepare_unified_td.py
```

打开生成的 `out/unified/AC201_AL_board_test.al`，或运行对应 `build_full.tcl`。
生成器验证 65 个工程引用（含字模、菜单模块），将工程 Path 绑定当前检出，
记录源文件哈希；不会调用 TD。原工程目录绑定问题的说明保留在
[统一构建记录](UNIFIED_BUILD_MENU_PHOTO_VIDEO.md)。本地仍需 TD syn/phy、
MEM/像素时钟时序检查及真机无卡菜单、按键和视频回归。

## 照片漂移

低影响候选是垂直消隐期同时复位读地址和读 FIFO，并将 LOAD 保持延长到
约 256 个像素时钟以排空在途突发。独立模型已复现旧版帧间漂移，并验证
候选五帧共 2,304,000 对像素帧间一致，覆盖一次在途读。**候选未合入本次
生产 RTL**，也未认定板上约 3 px/s 的精确速率已解决。详见
[照片漂移调查](PHOTO_DRIFT_INVESTIGATION.md)；D7 菜单显示已完全绕开这条路径。

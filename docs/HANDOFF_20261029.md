### 卡上内容（10-28 晚写入并校验）
```
槽 A（板子 LBA 1,000,000 / 物理 997,952）= INVADERS 606 词
槽 B（板子 LBA 1,001,000 / 物理 998,952）= BREAKOUT 492 词
```

### 开关映射（实测，与源码注释相反，以本表为准）
| SW6 | 板子读的 LBA | 内容 |
|---|---|---|
| **ON** | 1,000,000 | invaders |
| **OFF** | 1,001,000 | breakout |

- 卡带模式 = **SW7 ON + SW5 ON**；硬件版 = **SW7 ON + SW5 OFF**
- **热切换经常失败**（`WC=000`），换槽/换模式后**必须断电重上电**
- 判断是否真的加载：读遥测 `WC`（`25A`=606 词 invaders、`1EC`=492 词 breakout、`000`=没加载）

## 4. 音频：已确认的事 + 方案

### 已确认
- **HDMI 音频链路是通的**：`PSG → 音源选择 → audio_arc_calculate → HDMI 音频包`
- 用户实测：打砖块撞砖、击毁敌机**有"滴"声** ✓ 所以"音视频同源"不是虚标
- **codec（ES8388 耳机口）未接**：`I2S_DO=0`、`I2C` 被拉高 → 暂不做（现场用显示器耳机口）

### 待做（下一步主线）
见 `AUDIO_PLAN_20261028.md`，摘要：
1. **WAV 播放器**（1 天）：固定 LBA 流式读 → 4KB FIFO → 48k 立体声
   - SD 吞吐已算：SPI 25MHz ≈ **1.9 MB/s**，音乐需 0.19 MB/s → **10 倍余量**
   - 需要 **SD 总线仲裁**：卡带加载优先，空闲时音乐流式读
2. **混音器**（半天）：PSG + WAV **相加**（现在是二选一 mux）→ 音效与 BGM 共存
3. **菜单 UI**（1 天）：5 个应用条目 + "音乐播放"

### 音乐素材工具（已可用）
```powershell
python tools\music2sd.py --in 你的歌.mp3 --slot 0 --drive E   # 转格式 + 写卡
python tools\music2sd.py --drive E --list                     # 看 4 个槽
python tools\music2sd.py --in x.mp3 --slot 0 --out a.yxm      # 只转换
```
- **MP3 不能在 FPGA 里解**（要几千 LUT）→ PC 端 ffmpeg 转裸 PCM，FPGA 只做播放
- 槽位：板子 LBA `2_000_000 + i*98_304`（48MB/槽 ≈ 4.2 分钟 48k 立体声）
- 码率账：48k 立体声 = **11.5 MB/分钟**；`--mono` 减半；`--rate 32000` 再省

## 7. 铁律与坑（血泪，别重犯）

1. **改文件只用 Python 脚本**，不要用 PowerShell `-replace`（大小写不敏感，会把源码改烂）
2. **`design_top_wrapper.v` 是 GBK**，读写必须显式 `encoding='gbk'`
3. **PowerShell 命令行里的引号/`<`/`$`** 会把脚本解析成命令 → 补丁写成 `.py` 文件再跑
4. **改 RTL 先仿真再上板**，回归指标 `BADC0UNT=0`
5. **判定类 bug 先写 TB 打印矩形**，别盲改（10-28 两个 bug 都是这样定位的）
6. **`yxa` 把所有符号转大写** → `BSPD`/`bspd` 会撞名，用 `check_syms.py` 扫
7. **采集卡与 OBS 互斥**：OBS 开着 `grab.py` 报 I/O error，抓帧前先杀掉 `obs64`
8. **SD 写卡有 2048 扇区分区偏移**：板子 LBA 1,000,000 = 物理 997,952（`write_cart.py` 已补偿）
9. **换卡/换模式必须断电重上电**，热切换会 `WC=000`
10. **构建 10 分钟、烧写 26 秒**，一次只改一处，别叠加
11. **遥测口是 COM5**（不是 COM4），串口死了拔插 USB 线

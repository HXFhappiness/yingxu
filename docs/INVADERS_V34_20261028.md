## 1. 四个问题的真实原因与修复

| 用户反馈 | 真实根因 | 修复 |
|---|---|---|
| 屏幕中间有个不动的黄色方块 | **汇编符号撞名**：`BSPD`(0x24 数组) 与 `bspd`(0x35 速度) 归一后同名，后者覆盖前者 → 数组初始化写到了 0x35 之后 → `LDR [BSPD+X]` 读到别的变量 = 0 | 单字节变量改名 `bspd_cur` |
| 敌人不攻击 | 同上：炸弹速度 0 → 炸弹不动；且 `mactive` 一直是 1 → 再也不会投新弹 | 同上（一处修好两个症状） |
| 敌人太小不好打 | 绘制 `SW/SHT` = 24/16 px，命中判定中心距 <2q8 / <3q8 太紧 | 尺寸 24×16 → **48×32**；判定放宽到 **<7q8 / <5q8**；两架间距 7→8 q8 |
| 敌人左右往返 | `squads` 撞边后翻转方向（原地振荡） | 改为**始终向右、x≥154 从左侧重入**，每次穿越 `descend_t` 下压一行 |

卡带：`cartridges/invaders.asm`（479 词），已写卡 LBA 1,000,000（物理 997,952）。

## 2. 坑一：汇编器符号大小写归一（今天又踩一次）

`yxa.py` 把**所有符号转大写**，所以 `BSPD` 与 `bspd`、`score` 与 `SCORE` 是同一个符号，
**后定义的覆盖先定义的**。汇编不报错，运行到某处才表现为"读到的值是别的变量"。

**自检工具**：`python tools/check_syms.py cartridges\*.asm`
（今天扫描结果：14 个卡带里只有 invaders 一处撞名，已修。）

**纪律**：给单字节变量起名时避开所有数组名的大写形式。

## 3. 坑二：SD 卡写偏移（今天最大的误会来源）

卡是 **FAT32，分区起始在物理 LBA 2048**。`write_cart.py` 已内置偏移补偿，所以：

| 板子报告的 LBA | 物理扇区 | 内容 |
|---|---|---|
| 1,000,000 | **997,952** | invaders |
| 1,001,000 | **998,952** | breakout |

**验证方法**（卡插电脑时）：

```python
import struct
f = open(r'\\.\E:', 'rb')
for lba in (997952, 998952):
    f.seek(lba*512); b = f.read(64)
    print(lba, b[0x10:0x20].split(b'\x00')[0], struct.unpack('<H', b[8:10])[0])
```

⚠️ 直接读 `\\.\E:` 的 LBA 1,000,000 **不是**卡带（那是分区外/另一区域，会看到 FAT 数据）。
今天一度以为"写卡失败"，其实是查错了位置。

## 4. 坑三：SW6 选槽的真映射（与注释相反）

实测（`SW7+SW5` 保持 ON）：

| SW6 | 读出词数 | 内容 |
|---|---|---|
| **OFF**（SW=5F） | 362 = 0x16A | **breakout**（LBA 1,001,000）|
| **ON**（SW=1F） | 479 = 0x1DF | **invaders**（LBA 1,000,000）|

`hardware_test_P0_UART_V5_CRC32.v` 里 `CART_LBA_A/B` 的注释**写反了**，以本表为准。

**并且：拨 SW6 的热重载经常不生效（P1）**，判断是否真的换了槽，读遥测 `WC`：
- `16A` = breakout
- `1DF` = invaders
- `0` = 没加载（星空）

最可靠的换槽方式：**断电重上电**（SD 只在上电瞬间初始化）。

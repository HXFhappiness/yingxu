- 新增**血条**：3 命，SCORE 口显示（LED 低 4 位低有效）
- 球速：vxl 固定 2（工作区已改，**卡上还是 2..3 偏快版**）
- ⚠️ 编辑纪律：本轮 PowerShell -replace 把字面 `\r\n` 和 BOM 写进了 asm（已用 `tools/_fix_brk.py` 修复）——**改文件只用 Python 脚本**这条铁律再次验证

### invaders.asm v3.3（497 词，**工作区已就绪、未落卡**）
- 规格重做为 **3 型 × 2 架 = 6 架**：绿/黄/红三队
- 队速度分频 DIV：绿 3 / 黄 2 / 红 1（帧每步）；炸弹速度 BSPD：1/2/3 q8/帧
- 命中判定收紧：中心距 <3q8 → **<2q8**（擦边不杀）
- 数据布局：SX/SY 每架一份（队坐标按架复制），TDIR/TTICK/DIV/BSPD 也按架 6 项复制——
  **因为 X(R3) 是唯一变址寄存器，所有按架访问统一 `[基址+X]`，小队循环 X 按 0/2/4 步进**
- **本日最后一个 bug（已修，仿真验证）**：边界判断 BCS/BCC 用反——
  `CMPI R1,4; BCS sq_fl_l` 实际语义是"x≥4 就反弹"，导致三队每步都下压+右移 = 板上"敌机斜着飞"。
  已改为 `BCC`（x<4 左反弹）/ `CMPI R1,144; BCS sq_fl_r`（x≥144 右反弹）。
  仿真 y 直方图确认下压受控。
- ⚠️ 教训：**BCS/BCC 永远对着 CMPI 的无借位语义推一遍再写**；仿真要看"全过程直方图"而不是最后一帧

## 9. 补充：未落文档的关键经验（10-28 上午追加）

### 9.1 汇编层最容易犯的两个错（今天各踩一次）

1. **BCS/BCC 对着 CMPI 的"无借位"语义推反**（invaders 斜着飞）。
   `CMPI R1, N` 后：**C=1 ⇔ R1 ≥ N**（无借位），C=0 ⇔ R1 < N。
   写边界判断时先在纸上写一句"C=1 表示 x>=N"，再决定 BCS 还是 BCC。
2. **Y 只有 X(R3) 一个变址寄存器**。任何"二维表按队/按架访问"都必须
   把表展开成**每架一份**（复制存储），循环用 X 步进覆盖；不要试图用
   两个下标去算 `[基址+X+偏移]`——`SX+1+X` 这种写法看似对，实际是
   `SX[1+t]`，会跨到下一队的数据（今天 invaders 三队坐标互踩就是这么来的）。

### 9.2 仿真要看的不是"最后一帧"

今天两个 bug 仿真都"通过"了，因为只看了开头几条精灵提交：
斜着飞的 y 漂移、三队坐标互踩，都只有在**全过程统计**里才现形。
推荐手法（sim_ce 已备好 tb_burst2.v，提交上限放开到 4000）：

```
# 看外星人 y 的分布——正常应只有三档 (64/128/192 附近), 持续下压说明边界判断错
vvp tb_r7.vvp | findstr "slot=[2-7]"  → 统计 y 直方图
```

更要紧的一条：**模拟器(yxem)语义正确 ≠ RTL 正确 ≠ 板上正确**。今晚所有硬件 bug
都藏在"模拟器不建模、仿真单看开头看不出"的时序/存储细节里。三层验证缺一不可。

### 9.3 硬件游戏和卡带游戏是两套独立代码（别混淆）

构建里**同时**存在：
- `yingxu_invaders.v` / `yingxu_breakout.v`：**硬件 FSM 版**（纯 Verilog，不经过 CPU）
- SD 卡上的 `invaders.yxc` / `breakout.yxc`：**YX-8 卡带软件版**

用户报告"流浪者判别有误/移速慢"时先确认是哪一套：SW5 OFF 走硬件版、SW5 ON 走卡带版。
两者的手感参数要**分别**调（一个改 .v，一个改 .asm）。这也是答辩叙事里
"同一块板、同一屏、硬件游戏与自研 CPU 软件游戏并存"的实锤。

### 9.4 演示日操作纪律（血泪换来的）

- **卡插拔后必须断电重上电**——SD 只在上电瞬间初始化一次；热插拔后 LED0 灭、
  彩条/黑屏，看起来像"全炸"其实只是没初始化。
- **卡座接触是薄弱环节**：今天插拔 6+ 次后出现初始化失败，重插几次+断电才恢复。
  录演示前**一次性把两张卡带写好，之后不再拔**。
- **采集卡（OBS/ffmpeg）互斥**：OBS 开着时 grab.py 报 I/O error。抓帧前先关 OBS，
  或改用 OBS 自带截图。
- 换槽偶发被吞（P1）时**再拨一次 SW6** 即恢复，录演示可剪掉。

### 9.5 资源与时间余量

当前约 **9,000 LUT / 29 BRAM（45%）**，还有余量——但**不要**在 11.2 冻结前做
结构性改动（历史教训：RTL 结构变化会重掷布局，SD 初始化可能挂掉，得重新扫种子）。
冻结前的改动只允许：卡带 .asm 参数、纯组合小逻辑。

### 9.6 如果时间只剩一天，做什么

按性价比排序：①写卡落 v3.3 并板上验收（30 分钟）→ ②录演示视频（1 小时）→
③补答辩材料里"三层调试链"那一段（这是自研 CPU 最硬的含金量）→

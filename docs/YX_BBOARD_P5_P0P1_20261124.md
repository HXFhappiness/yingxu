## 2. 根因：BRAM 池容量，不是推断写法

综合日志里的一行才是真因：

```
SYN-2599 : Bram u_top/u_band/book will be implemented by dram for resource limit
         in .../yx_vp_band.v(76)
```

- 全设计 BRAM 需求 ≈ 740 Kbit（码本 256 K + 行缓冲 160 K + 索引 map 56 K
  + 以太网 FIFO 64 K + HDMI 核 FIFO ~120 K + SDRAM FIFO 64 K + …）；
- 9Kb 池只有 64 × 9 Kbit = **590 Kbit**；
- 资源受限时 TD 把 `book` / `ln32` 一起踢成分布式 RAM → 20~30K LUT；
- 器件另有 **16 块 bram32k = 64 KB 完全闲置**，但 TD 的 RTL 推断路径**永远不分配它**。

### 已排除的推测（都试过，`bram32k` 始终 0/16）

| 尝试 | 结果 |
|---|---|
| 深度补成 2 的幂（5120 → 8192） | 无效 |
| 读地址改为寄存器 | 无效 |
| 写口做成全寄存端口（we/wa/wd 各打一拍） | 无效 |
| 写口移出带 `negedge rst_n` 的大 always 块 | 无效 |

### 正解：显式例化 `EG_LOGIC_BRAM` + `IMPLEMENT="32K"`

原语定义见 `TD_Release_2026.2.210.850/arch/eagle_macro.v:986`，
参数含 `IMPLEMENT = "9K" | "32K" | "AUTO"`。工程里原本就有仿真 shim
`tb/bshims/EG_LOGIC_BRAM.v`（1 拍同步读、字节使能、DP 模式），说明这条路此前探过。

`yx_vp_band` 里 `ln32` 的例化（8192×32 → 8 块 32Kb）：

```verilog
EG_LOGIC_BRAM #(
    .DATA_WIDTH_A(32), .DATA_WIDTH_B(32),
    .ADDR_WIDTH_A(13), .ADDR_WIDTH_B(13),
    .MODE("DP"), .REGMODE_A("NOREG"), .REGMODE_B("NOREG"),
    .IMPLEMENT("32K")
) u_ln32 (
    .dia(ln_wd_r), .addra(ln_wa_r), .cea(1'b1), .wea(ln_we_r), .clka(clk), ...
    .dib(32'd0),   .addrb(scan_ra[13:1]), .ceb(1'b1), .web(1'b0),  .clkb(clk),
    .doa(),        .dob(scan_rd32_w)
);
```

> 副作用（正向）：`book` 也顺便回到 BRAM（9Kb 池腾出空间后不再被踢）。

## 3. P0 行缓冲：32bit 打包 + 单读口

原实现是 16bit × 双读口组合读（`scan_rd` / `scan_rd_b`），BRAM 无法承载。

改造：**按 32bit 打包**（每字 = 相邻偶/奇两个 RGB565），端口从 3 个减到 2 个
（1 写 + 1 读）——而且这**不是妥协**：扫描端消费的本来就是 32bit 打包字
（`sc_wdata = {奇,偶}`、`sc_ra += 2`）。

写侧：块内 16 像素按行主序写，`wp[1]=0` 装列 (0,1)、`wp[1]=1` 装列 (2,3)，
偶像素经 `pix_hold` 暂存一拍照打包。

## 4. 本轮踩到的 4 个坑（都不是"资源"问题）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 全字错，`GOLDEN=2304000`（=900 带 × 2560 字） | `pix_hold` 声明成 **1 bit**，`{book_rdata, pix_hold}` 变 17 位零扩展（实测 `0x00000402` 恰好 = `{0x0201, pe[0]}`） | `reg [15:0] pix_hold` |
| 2 | 部分地址 `ln=xxxx`（SYS 日志 b=0 w=640 起） | 行缓冲写地址用了 `wp[2:1]`，把"行内列号"与"行号"搅在一起 → 行 1/2/3 各偏 +2/+4/+6 字，每行前 2 字永不被写 | 改为 `wp[1]` |
| 3 | 奇半区全错 | 读地址钳位条件用了**半区**尺寸 2560，应为**数组**尺寸 5120 | 修正上界 |
| 4 | 每 128 字错 1 字（`sdram[k]=ln[k+1]` 且 `sdram[k+1]` 同值） | 推数**相位**偏移 1 拍（或写使能与地址推进分属两拍）：FIFO 满停顿一拍即丢一字+重一字 | 见 §4.1 |

### 4.1 这条最容易复发：推数相位对控制器是致命的

厂商 `Sdram_Control_4Port` 的写通道按"占用 > AE(127)"触发突发，且
**对推数相位极敏感**（`YX_BBOARD_P5_TD_20261123.md` 已记过一次同类整字错位）。

判定手段（本轮新增，已保留在 TB 里，`-DP0_TRACE` 打开）：

```
PTR-DIFF k=635 pt=01ab01aa ln=01a201a1 sdram=01ab01aa | prev pt=... | next pt=01ab01aa ln=01ab01aa
```

它把"推入 FIFO 的数据流（`u_top.wr1_en`/`sc_wdata` 逐拍影子队列）"与行缓冲逐字对齐，
从而一刀切开两种可能：
- `pt !== ln32` → 扫描推数流本身错（本次命中）；
- `pt === ln32` 但 `sdram !== ln32` → 控制器写路径错（早前 PRIME 版曾命中）。

配合已有的 `FIFOPOP wr1: pops/mismatch/underrun` 三计数，可以完整定位到"数据错"
还是"地址/时序错"。

**最终采用的结构**（与已双门禁 PASS 的 032049 版逐拍一致，只换存储实现）：

- `sc_ra` 在 **LOAD 拍**预置为带内半区基址；
- `wr1_en` 是**寄存器**（PUSH 拍置 1，下一拍入 FIFO）；
- `WR1_DATA` 直连行缓冲的寄存输出（原语 B 口读延迟正好 1 拍，与旧版 `sc_wdata`
  寄存级等价），首推落在 `LOAD+1`、第 k 拍推 `ln[k]`；
- 不要改成组合 `wr1_en`、不要插空拍、不要把地址推进与写使能分开（三者都会错位）。

## 5. 下一步（P2b：唯一剩余时序项）

1,033 条违例全部来自 `u_ixdec/map_ram`：
`u_top/REAL_IX$u_ethrx/rem_reg → u_top/u_ixdec/map_ram_syn_*.e[0]`，
slack −1,031 ps，逻辑 10 级（`LUT5×4 + LUT4×3 + LUT3 + LUT2 + DRAM`）。

`map_ram` 是 57,600 × 1 bit 的"已变更块位图"，当前是 LUT 分布式 RAM 且**组合读**
（`if (map_ram[blk])` 同拍决策）。修法：

- 打包成 8 bit/字（`map8[0:7199]`，每字 8 个块）= 57,600 bit → 2 块 32Kb 原语；
- 读改为同步读（地址 = `blk[16:3]`，输出打一拍），决策延后 1 拍；
- blk 在补丁路径上是顺序推进的，可做**预取**（提前一拍给出下一块的地址），
  对吞吐无影响。

预算：`bram32k` 余 8 块（本项用 2 块），`#lut` 还有 39% 余量。

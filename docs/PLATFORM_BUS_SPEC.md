# 映序系统总线规范（YXB v1.0）

> 状态：草案（依据 D43 位流与 `yx8_cart_soc.v` / `yxem.py` 现状整理）
> 适用：YX-8 卡带、平台固件、PC 端工具链
> 目的：把"外设寄存器"升级为"平台契约"——任何卡带以同一套方式访问硬件，
> 平台按卡带声明配置自己。这张表冻结之后，谁都不许单方面改。

---

## 1. 地址空间

YX-8 是 8 位处理器，地址与数据均为 8 位；程序另有一套 10 位字地址空间。

| 空间 | 范围 | 宽度 | 说明 |
|---|---|---|---|
| 程序 RAM | 0x000–0x2FF（0–767） | 24 bit/字 | 卡带代码，装载后只读执行 |
| 数据镜像区 | 0x300–0x3FE（768–1022） | 24 bit/字 | 卡带 DATA 段的原始镜像 |
| 描述符 | 0x3FF（1023） | 24 bit/字 | 装载器写入 `{data_addr, data_len}` |
| 数据 RAM | 0x00–0xDF（224 B） | 8 bit | 可读写，断电即失 |
| **I/O 窗口** | **0xE0–0xFF（32 B）** | 8 bit | 外设寄存器，见第 2 节 |

约束：`data_addr + data_len ≤ 0xE0`，即 DATA 段不得越界进入 I/O 窗口。

## 2. I/O 端口表（v1.0，已实现）

| 地址 | 名称 | 方向 | 语义 |
|---|---|---|---|
| 0xE0–0xE7 | `BRICK[0..7]` | 读/写 | 砖块位图，共 60 bit（8 字节，bit0 = 第 0 块），10 列 × 6 行，行优先 |
| 0xE8 | `SPR_EN` | 写 | 精灵暂存：使能 |
| 0xE9 | `SPR_XL` | 写 | 精灵暂存：X 低字节 |
| 0xEA | `SPR_XH` | 写 | 精灵暂存：X 高字节 |
| 0xEB | `SPR_YL` | 写 | 精灵暂存：Y 低字节 |
| 0xEC | `SPR_YH` | 写 | 精灵暂存：Y 高字节 |
| 0xED | `SPR_W` | 写 | 精灵暂存：宽（7 bit） |
| 0xEE | `SPR_H` | 写 | 精灵暂存：高（6 bit） |
| 0xEF | `SPR_CL` | 写 | 精灵暂存：颜色低字节（RGB565） |
| 0xF0 | `SPR_CH` | 写 | 精灵暂存：颜色高字节 |
| 0xF1 | `SPR_COMMIT` | 写 | 提交：把暂存内容写入槽 `n`（0–15） |
| 0xF2 | `KEYS` | 读 | bit0 = KEY0，bit1 = KEY1，其余保留为 0 |
| 0xF3 | `FRAME` | 读 | 帧计数，每帧 +1，自然回绕 |
| 0xF4 | `RAND` | 读 | 硬件 LFSR 随机数（每帧推进，种子 0xAC） |
| 0xF5 | `PSG` | 写 | 音效事件码：0=撞砖 1=撞板 2=坠落 3=清屏/胜利 |
| 0xF6 | `SYS` | 读 | 当前硬件返回常量 `0x80`（vblank 位）；bit1:0 的卡带号在模拟器中实现，硬件尚未接入 |
| 0xF7 | `PAD_LO` | 读 | PS2 手柄按键位图低字节（↑↓←→ × ○ □ △ L1 L2） |
| 0xF8 | `PAD_HI` | 读 | PS2 手柄按键位图高字节（R1 R2 L3 R3 SELECT START 保留） |
| 0xF9 | `PAD_LX` | 读 | 左摇杆 X（0–255，中位约 128） |
| 0xFA | `PAD_LY` | 读 | 左摇杆 Y |
| 0xFB | `PAD_RX` | 读 | 右摇杆 X |
| 0xFC | `PAD_RY` | 读 | 右摇杆 Y |
| 0xFD | `CAPS` | 读 | 平台能力寄存器（YX-8.1 起生效）：bit0=`CAP_YX81`（16 位寄存器对指令 0x60–0x68 可用），其余位保留读 0 |
| 0xFE | `SCORE` | 写 | 底部状态条点亮段数（0–8），同时用于 LED 备份显示 |
| 0xFF | `EXT` | 读写 | **扩展总线命令口**：transport = 千兆以太网（见 4.4） |

### 2.1 写语义

- **全部为写即生效**，无握手、无等待周期。
- 精灵采用"暂存 + 提交"两段式：先写 0xE8–0xF0，再写 0xF1 提交；提交前不改变显示。
- 下一次写入 0xE8 开始新一轮暂存，未提交的暂存内容被丢弃。

### 2.2 读语义

- `KEYS`、`FRAME`、`RAND`、`SYS` 为组合读取，任意时刻可读。
- `SYS` 的 vblank 位在垂直消隐期间为 1，供卡带做帧同步。
- 写 `SCORE`/`PSG`/`BRICK` 后立即读回不保证返回写入值（写寄存器为单向）。

## 3. 时序约定

| 项目 | 值 | 说明 |
|---|---|---|
| CPU 时钟 | 73.33 MHz（像素域） | 卡带代码执行域 |
| 装载器时钟 | 50 MHz（系统域） | SD 读取与装填，与 CPU 异步 |
| 帧率 | 59.2 fps | `FRAME` 与 vblank 的时基 |
| 装载完成 | `cart_ready` 置位后 CPU 才启动 | 卡带无需关心装载时序 |

**卡带不得依赖指令周期数**：像素域与系统域异步，同一段代码在不同负载下的绝对时间可能不同。需要定时请用 `FRAME`。

## 4. 扩展规则（v2 起生效）

这是把"寄存器"变成"平台"的关键：**新增外设不许改已有的地址**。

1. **保留区分配**：0xFD 为最后 1 字节保留位，其余按外设粒度分配（建议每个外设 1–2 字节寄存器，其余为数据口）。
2. **能力位协商**：卡带头里的 `flags`（见《卡带头格式》）声明所需外设；平台若缺少该外设，**拒绝启动**并在 `SCORE` 口显示错误码。
3. **版本字段**：`SYS` 口读数保留 bit6:2 给平台版本（v1.0 置 0），卡带可据此做降级。
4. **扩展总线（0xFF）**：板间链路的命令口。**物理层为千兆以太网**（两块板各带 RTL8211 PHY，直连即可），不再是 40-pin 排针；帧格式见《扩展总线协议》（待起草，传输层复用厂商 RGMII/UDP 栈）。40-pin 排针整排释放，改作外设接口（手柄/键鼠/调试引出）。

## 5. 与现有实现的对应

| 规范条目 | RTL / 工具 |
|---|---|
| 数据 RAM、I/O 窗口 | `yx8_cart_soc.v` 的 `dram` 与 I/O 译码 |
| 砖块位图 | `MASK 0xE0` → `brick_mask[59:0]` → 精灵引擎砖块层 |
| 精灵暂存/提交 | `SEN/SXL..SCH/SCOMMIT` → 精灵引擎槽写口 |
| KEYS / FRAME / RAND / SYS | 卡带 SoC 的按键、帧计数、LFSR、vblank |
| PSG | `yingxu_psg.v` 事件译码 |
| SCORE | 底部状态条（8 段）+ LED |
| 卡带装载 | `write_cart.py`（写卡）、`yxem.py`（模拟器参照实现） |

> **一致性判据**：任何对 I/O 语义的修改，必须同时改 `yxem.py` 并通过 `tb_yx8_cosim.v` 的黄金轨迹比对；模拟器与硬件不一致视为缺陷。

## 6. 待确认项（起草时核对代码发现的不一致）

- `SYS`（0xF6）硬件恒返回 `0x80`，模拟器却返回 `0x80 | 卡带号`。**这是一处软硬件不一致**，按"模拟器为准"的判据应视为缺陷；建议要么硬件补上卡带号，要么规范只写 `0x80`。
- `SYS` 口 bit6:2 目前未使用，可留给平台版本上报。
- `SCORE` 的段数上限 8 与 `SEG_MASK` 相关（当前 `IMG_COUNT=9`，实际点亮 8 段）。
- `PSG` 事件码 0–3 由 PSG 模块解释，新增音色需在 `yingxu_psg.v` 中扩展并在此登记。

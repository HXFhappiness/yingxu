# 音乐无声根因：consume_acc 16 位溢出（2026-10-30 晚）

> 修复固件：**g30**（`out/build_g30.txt`，bit 时间戳 20:xx）
> 回退位：`out/bitstream_backup/g29_rates.bit`（只有遥测，音乐仍慢放）

## 症状

SW4+SW7 ON、SW5/SW6 OFF（纯音乐模式）下听不到音乐，只有每隔几秒的杂音。
游戏音效正常。g27 LED 显示 LED0/1/2 常亮、LED3 高频闪。

## 定位过程（全部靠仪表，不靠猜）

1. **g27 LED**：LED3 高频闪 → 断流看门狗在每 1.31ms 反复触发。
   查代码发现阈值(65535 拍 @50MHz)比 SD 单扇区取数时间(~0.7-1ms)还短，
   每个扇区间隙必然误报。**这是真 bug，但不是静音的根因**（重启请求会被
   探针 `restart_hold` 排队，不打断当前块）。
2. **g28 遥测**：把 rptr/pops/occ/wptr/sstate/看门狗/lastL 挂到 COM5 的
   卡带调试字段（音乐模式 mux）。实测：
   - sstate=1（S_PLAY 达成）、occ=768（FIFO 满水位）、看门狗 0 次（修复生效）
   - **pops 只有 4561 次/秒**（应 44100）
   - rptr/wptr/pops 三者严格同步，说明整条流水线被弹出速率限死
3. **本地文件头**：`going_home.yxm` 是 **44100Hz**（hdr 字节 `44 AC`），
   不是 48000。
4. **Python 复算累加器**：rate=44100 时算出 **4559 次/秒**——与板上 4561 吻合。

## 根因

```verilog
reg [15:0] consume_acc;              // 16 位
consume_acc + rate_pix >= OUT_HZ     // 16 位上下文求和
```

`consume_acc + rate_pix` 在 16 位宽度下求和，和 ≥65536 时**静默回绕**：

- `rate = 48000` 时 `consume_acc` 恒为 0（和不超过 48000），恰好不溢出 →
  仿真用的 48k 测试音永远测不出来；
- `rate = 44100` 时累加器被反复截断 → 实际只有 4559 次弹出/秒 →
  音乐以 **1/9.7 速度**播放；HDMI 仍按 48kHz 送出，每个样本被重复约 10 次
  → 听感是低频嗡嗡/杂音，完全无法辨认旋律。

## 修复

`consume_acc` 改 32 位，并且只在未触发时才累加（写成分支，避免重复赋值）：

```verilog
reg [31:0] consume_acc;
if (out_tick) begin
    if (consume_acc + rate_pix >= OUT_HZ) begin
        consume_acc <= consume_acc + rate_pix - OUT_HZ;
        rate_tick   <= 1'b1;
    end
    else consume_acc <= consume_acc + rate_pix;
end
```

## 回归测试升级（关键）

原测试台只用 48kHz 的文件，正好绕过该 bug。现在：

- 测试台支持 `+file=<路径>` 参数；
- 新增 `RATECHK` 判据：**pops / out_tick 应等于 rate/48000**，
  与时钟频率无关，溢出类 bug 必然暴露；
- 新增 44.1kHz 测试文件 `out/tb_tune44.yxm`（`tools/_mk44.py` 生成）。

结果：

| 文件 | pops/out_tick | 期望 | 结论 |
|---|---|---|---|
| tb_tune.yxm (48k) | 0.9998 | 1.0000 | PASS |
| tb_tune44.yxm (44.1k) | 0.9185 | 0.9187 | PASS |

修复前 44.1k 该比值约为 0.095。

## 教训

1. **测试激励要覆盖真实参数**：48k 恰好是唯一不触发溢出的采样率，
   等于给 bug 开了后门。
2. **比值型判据 > 绝对数量判据**：pops 数量本身正常（24000 个都弹出了），
   只有"每秒弹出数"才暴露问题。
3. 16 位算术的隐式截断在 Verilog 里不会报错，累加器/计数器要用足够位宽，
   或在表达式里显式拓宽（`{1'b0, a} + b`）。

## 遥测字段（音乐模式下，g28 起）

D 帧在音乐模式下被 mux 成播放器内部量（卡带模式仍为原卡带调试字段）：

| 字段 | 内容 |
|---|---|
| `MISE` | out_tick 计数（测 PSG 节拍） |
| `SCE`  | byte_v 计数（测 SD 吞吐） |
| `SP`   | YXMA 头解析出的 rate |
| `PC`   | wav rptr[9:0] |
| `DW`   | pops 累计 |
| `I0`   | {sstate, occ, wptr} |
| `RC`   | 看门狗触发次数 |
| `I1`   | {8'd0, last_L} 最近写入的左声道样本 |
| `SW`   | 开关字节（0x6F = 4+7 ON、5+6 OFF） |

抓取方法：

```
powershell -File tools\music_telem.ps1 -Seconds 6
python tools\music_telem.py
```

**★ TD 约束坑（本轮新踩，SDC 写输入延时必看）**：虚拟时钟的 `period` **不参与**
输入路径的预算——TD 的 Budget 取的是**捕获时钟周期**。首版把 `b_mdio_virtual`
写成 400ns、`-max 195`，报告里 Budget 仍是 `clk0 rising@10.000 - virtual rising@0.000
= 10ns`，于是 SWNS = **−182.966ns**，把本来干净的 100M 域拖出违例。改成
`-period 10.000` + `-max 4.5 / -min 4.0` 后回到 SWNS 0.000（`eth_mdio`
setup +7.099ns / hold +0.240ns）。

**★ `RXD0/RXDLY` strap 极性已不再是阻塞项**：MDIO 序列无条件把页 `0xd08`/
寄存器 `0x15` 的 bit3 清 0，而内核 `rtl8211f_config_rgmii_delay()` 明确
`RGMII_RXID` 写 1、`RGMII` 写 0（bit3=1 即延时使能）。strap 只决定初值、
不改变语义 → 两种极性下都收敛到"延时关闭"（原本=0 时写回同值，幂等）。

**★ 新增一条坑（TB 侧，写模型时容易重犯）**：PHY 行为模型里 `edge_cnt` 的递增
**不能**被 `mdio_oe` 门控。读操作从 TA（bit46）起主机释放总线，若计数器同时冻住，
PHY 端 `edge_cnt 48..63` 的数据驱动条件永不成立，读回值恒为 0（实测 `rxcr_r=0000`
而非 0x1238，进而把 RXCR 其他位全写成 0）。只有 `phy_rx` 移位和 `ones_cnt` 计数
才该受 `mdio_oe` 门控。另两条：`reg rst_n = 1'b0` 是初值不是跳变（`negedge rst_n`
复位分支不执行 → 状态恒 X → 首帧整帧丢失）；`edge_cnt` 位宽要能表示 64。

**遗留**：`PHY_INIT_WAIT=100ms` 是保守取值未按数据手册核算；序列跑完无读回校验
（`rxcr_r`/`cfg_skip` 只在顶层内部，无空闲引脚可观测）；RGMII 输入 hold
（−3.237ns / 10 端点）仍未处理，属 §1.1 的已知拓扑/判据冲突。

## 2.5 长仿真与超时（2026-11-23 实测，务必遵守）

### 铁律

1. **一律后台跑 + 轮询日志**，不要在前台等。前台即便给到 600 s 也一定先超时，
   被杀的进程不会留下 VERDICT —— 这就是"反复等待超时"的真正原因。
2. **判定只看 `VERDICT:` / `GATE` / `TB-SUMMARY`**；`exit=0` 不是通过。
3. **心跳看 `POLL t=`**：间隔已是 **250k 拍**（12M 下 48 行；eth 速度约 37 s 一行）。
   `t=` 在涨就是活着。
4. **"日志不涨 ≠ 卡死"**：用 `Get-Process vvp | Select CPU` 采两次，
   20 s 内涨约 20 s（=100% 占用）说明正在算，不要杀。
5. **迭代期把 `WD` 降到 4M/6M**（单轮约 7 分钟），**只在最终验收跑 12M**。

### 已踩过的坑：打印风暴

`bboard_sys_eth_20261123_182719` 曾产生 **2.4 MB / 204,002 行**日志，其中
**199,978 行是 `FEED 0: 00`**（98%），日志 I/O 把仿真拖到爬行继而超时。

原因：以太网模式下码流由 eth 驱动，TB 的 `sent` 恒为 0，而探针条件
`sent < 12 && s_ready` 每拍成立 → 每拍打印。

**规则**：TB 里任何"只打前 N 次"的探针必须用**独立计数器**（如 `feed_cnt`），
不能复用被别的路径驱动的变量。当前代码已改为独立计数 + `$fflush` 实时落盘。

## 5. 已踩过的坑（改代码前必读，详见各源码注释与文档）

1. **顺序突发口的 LOAD 地址必须 64 字对齐**：full-page 突发在行边界（256 字）内回绕，
   未对齐会周期性错位且被均匀区域掩盖（实测 1585 字错）。
2. **`rWR*_MAX_ADDR` / `rRD*_MAX_ADDR` 只在复位锁存**，LOAD 不锁 MAX。
   依赖 MAX 回卷的"整窗循环读"会在第二个窗口死循环。解法：MAX 恒全域，回卷靠显式 LOAD。
3. **写 FIFO 的 AE 阈值 = 突发长度**：盲推 1 字/拍会在窗尾滞留不足一次突发，
   永不触发末突发或中途欠载。解法：按 128 字成组推进。
4. **显示 `valid` 不能直接用源的输出**：源在行末多出 2 拍（落进消隐），按拍计数会被
   当成下一行前 2 像素 → 每行首字重复。解法：由 `pixel_active` 延迟 8 级生成（VDLY）。
5. **防撕裂闸门的"显示窗"必须取 `i_base` 实际指向的窗**，不能用实时 `win_show_req`，
   否则换窗瞬间会放行对正在显示的窗的写入。
6. `.gitignore` 里的中文注释**不要用 PowerShell 改写**（GBK 往返会毁文件）。用 Edit 工具或
   显式 UTF-8 的 Python 脚本。

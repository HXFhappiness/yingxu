# YX_BBOARD_P5_LED_20261124 — 板级状态指示灯（把"哑板"变成能自述状态）

> 承接 `YX_BBOARD_P5_MDIO_20261124.md` §9.2 的遗留项
> （"`rxcr_r`/`cfg_skip`/`cfg_done` 没有空闲引脚可观测"）。
> **该判断当时是错的**：AC201 的 4 个用户 LED 在 `IO_b.adc` 里一个都没约束。
> 未生成 bit、未烧录。

## 1. 为什么需要它

B 板上板后如果收不到包，此前**无法区分**下面四种原因：

1. PHY 没上电/没复位（RXC 没有）
2. MDIO 配置序列没跑完，或 PHY 无响应
3. RGMII RX 时序不对（采样点落在数据眼外）
4. 码流根本没发过来

这四件事里，(2) 恰好有一条"能直接看"的状态：`yx_b_phy_init` 的
`rxcr_r`（读回的 RXCR 原值）、`cfg_done`、`cfg_skip`。它们本来已经在顶层内部，
只是没引出。4 个 LED 正好够用。

## 2. 位定义

| LED | 引脚（`D:\pin_table.txt:132-136`） | 内容 | 判读 |
|---|---|---|---|
| `led[0]` | M12 | `phy_cfg_done` | 序列跑完置 1 |
| `led[1]` | R16 | `phy_cfg_skip` | **仅当 PHY 无响应**（MDIO 读回 `0xffff`）时置 1。注意：没有"无需改"这条路径——序列是"无条件清 bit3"，bit3 原本为 0 时同样走完整写流程，`cfg_skip` 仍为 0 |
| `led[2]` | R15 | `phy_rxcr_w[3]` **清除前**的值 | **= RGMII RX 延时使能位**（扩展页 `0xd08` / 寄存器 `0x15` bit3），把 strap 状态从推断变成实测。⚠ `cfg_skip=1` 时该位恒为 1（`0xffff` 的 bit3），属假阳性——先看 `led[1]` 再看 `led[2]` |
| `led[3]` | T15 | `clk100` 心跳（100 MHz ÷ 2 ÷ 33e6 ≈ 1.5 Hz 周期） | 闪 = 时钟与配置逻辑在跑 |

## 3. 上板第一眼判读表（这是本改动的主要价值）

| 现象 | 结论 | 下一步 |
|---|---|---|
| 灯全灭、心跳不闪 | 50M 晶振/复位/供电没起来，或 PLL 未锁定 | 先量 K14 时钟、H14 复位 |
| 心跳闪、`cfg_done=0` | 序列没跑完：PHY 复位或 MDIO 时钟（`clk100`）异常 | 量 C15 `eth_rst_n`、C16 `eth_mdc` |
| 心跳闪、`cfg_done=1`、`cfg_skip=1` | **PHY 无响应**（MDIO 读回 `0xffff`） | 查 D14 `eth_mdio` 上拉/接线、PHY 供电 |
| `cfg_done=1`、`cfg_skip=0`、`rxcr3=1` | strap 原本**使能**延时，序列已清掉 → "绕过而非解决"的疑问闭环，且延时确实关了 | 收包应正常；若仍不收，问题在 RGMII 时序或码流 |
| `cfg_done=1`、`cfg_skip=0`、`rxcr3=0` | strap 原本就是关闭，序列写回同值（幂等） | 同上，直接查时序/码流 |

> `rxcr3` 是**清除前**的原值，所以它回答的是"硬件 strap 到底是什么状态"，
> 而不是"我们写了什么"——这正是之前只能靠推断的那一问。

## 4. 极性

AC201 原理图上 LED 未标注驱动极性（引脚直驱 / 经三极管无法从 RTL 判定）。
顶层加了参数：

```verilog
parameter LED_ACTIVE_LOW = 1'b0   // 默认：驱动 1 = 点亮
```

若上板发现整体反相（心跳灯"常亮不闪"就是反相的典型表现），把该参数置 1 即可，
不需要改别的。心跳是 50% 占空比，反相后仍能看出"在闪"，所以极性不会掩盖心跳判读。

**改哪里**：`src/user_source/hdl_source/media/vp/yingxu_vq_board_top.v:39`
（模块参数列表的最后一项）。板级 wrapper `yingxu_vq_board_b.v` **没有透传**该参数
（它只传 `SIM_ABSTRACT` / `LOCAL_MAC` / `LOCAL_IP` / `LOCAL_PORT`），
所以只能改顶层默认值——这也是唯一一处，改完重新综合即可。

> 之所以不做成 `-define`：TD 流程虽然已经用 `-define "EMIT_HDMI USE_ETH"`，
> 但极性反了本来就必须重新综合出 bit，改一行源码与加一个宏的工作量相同，
> 多一套机制只是多一处可能不同步的地方。若将来发现需要频繁切换再改成宏。

### 4.1 ★ 心跳分频器的位宽 bug（已修）

初版把分频值声明成 24 位：

```verilog
localparam [23:0] LED_HB_DIV = 24'd33_000_000;   // ← 装不下
reg [23:0] led_hb_cnt;
```

**24 位最大只有 16,777,215，而 33,000,000 需要 25 位** → 常量被静默截断成
**16,222,784**，心跳实际约 **3.08 Hz**，不是文档当时写的 1.5 Hz。

为什么差点漏掉：`iverilog` 只给一句
`warning: Numeric constant truncated to N bits`，**不挡编译、不影响任何仿真判据**
（LED 是纯输出），TD 也不报错。而心跳快一倍，板子上肉眼很难分辨"1.5 Hz 还是 3 Hz"，
所以这个错误可以一路带到上板。

修法：`[23:0]` → `[24:0]`，所有相关常量同步改 `25'd`。修后 iverilog 无截断警告。

> 教训：**凡是"只看现象、不参与判据"的输出（LED/蜂鸣器/心跳），最容易藏这种错**——
> 没有任何门禁会拦住它。这类代码要么加一条断言，要么像这里一样把位宽算式写进注释。

## 7. 后续可选（都还有引脚）

- **七段数码管**（SEG7_SCLK/RCLK/DIO = T14/R12/R14，空闲）：3 线串行扫描，
  约 50 行驱动就能显示多位十六进制，适合看 `byte_cnt` / `commit_no` / `pkt_drop_cnt`。

- **KEY0/KEY1**（F7/E7，空闲）：可做运行时切换（如强制重跑 MDIO 序列、冻结画面）。

# D3 顶层集成实施约定（2026-11-01）

基线feat/mjpeg@a35f9ef。先写本约定，再按适配、SD供给、显示、音频/遥测逐步提交并推送；main、冻结bit、厂商src/5640、al_ip和HDMI IP不改。板上TD综合/时序/烧录由用户完成。

## 数据与内存

首版继续640×480@24、最多512帧。视频模式独占SDRAM媒体区域，照片模式退出后重载，不能将照片缓存与视频PCM同时当永久驻留。32bit word地址：RGB A=0x000000，B=0x040000（各153600word）；JPEG双槽0x080000/0x084000（各64KiB）；PCM=0x100000至0x200000（4MiB）。PCM实际至多4096000B，按YXV头/时长检查，不向8MB外写。帧表512×64bit存自研小RAM，D3单列4块BRAM，不能隐藏到D2原5块估算里。

启动读YXV头/帧表并校验magic/version/640×480/24/48k stereo、帧数1…512、表项512对齐、长度4…65535、无重叠、音轨长度和时长；按末帧对齐末端求audio_off。PCM整段先经同一12.5MHz SD链路预载到SDRAM，播放期SD按帧表预取JPEG，两个槽与解码、呈现流水重叠。PCM预载有显式启动等待，算在启动时间，不混入播放吞吐。

因此播放期SD只需budget JPEG含填充约1.119MB/s，小于板测约1.30MB/s；PCM播放从SDRAM读取约0.192MB/s，保留WAV原FIFO/增益/48k节拍。此选择没有提高压缩、降低fps或改素材，代价是启动PCM预载和4MiB SDRAM保留；支持512帧21.33秒边界，演示仍≤21秒。

## 物理服务与时钟

新burst适配器在控制器100MHz域预存最多8word写数据，再给四口控制器服务状态机地址/长度；读响应先收齐再R/V排出。直接复用原IN_REQ/OUT_VALID及mWR_DONE/mRD_DONE，真实完成后才通知decoder。禁止用WR2_LOAD清FIFO模拟随机突发。仅修改自研yingxu_sdram_control_4port，参数关闭时保留原调度；视频运行时物理刷新>RD2显示>解码写>其他（预取、PCM服务等），owner保留至物理完成。

D2 decoder/arbiter保持100MHz。sys50 SD事务和8bit字节通过有背压的跨域FIFO/mailbox传至100MHz；SD探针增加动态LBA/count兼容入口，默认5401扇区旧模式保持，厂商协议层不动、DRAIN_1CYC=0。播放控制不使用pix组合反馈，跨域计数用Gray同步，帧完成与前台交换用held-bus/toggle。

## 显示与音频

成功解码只发布后台；pix垂直消隐接收帧交换，再确认释放旧前台。输出1280×720中间640×480窗口（x320…959/y120…599），RGB565 word高16位为先像素，边界黑色。RD2沿现有framebuffer物理路径，解码写不复用BMP FIFO。音频YXV raw PCM经合成32B YXMA头与原yingxu_wav_player消费，循环时按原歌曲重启握手重放头，不能丢PCM尾样本。视频时基以实际音频pop的32bit计数推进，每2000个立体声帧一视频帧；接收/解码计数不能冒充呈现或播放进度。

## 模式、回退、遥测

物理SW7 OFF + SW4 ON + SW3 ON进入视频（管脚sw7=1/sw4=0/sw3=0），首版固定视频槽0，LBA3000000。其他组合走原模式。进入/退出在sys域去抖同步，退出或失败先排空已接受内存事务再释放所有者；失败sticky并回退照片模式、触发照片重载，禁止无限自动重试。再次进入需拨出再拨入。

D帧按视频模式复用已有字段：PC=呈现帧号低10bit，DW=丢帧计数，MISE=解码完成计数，SCE=SD占用/累计扇区等，P0包含视频状态/错误码/运行位，RC=音频pop低16bit；完整定义与实际实现一并更新。保留旧音乐/卡带字段含义。模式请求/播放/回退三个状态必须可区分。

## 验证门禁

先用真实四口服务状态机加事务模型测试1…8word读写、首尾、读/写反压、物理done、显示插入；厂商协议/PHY可建模但不得将D3控制/调度/decoder替换成预制帧。供给测表界、PCM逐字节、JPEG槽不覆盖占用帧；显示测完整地址/颜色/消隐交换；音频测48k RATECHK和逐样本、循环尾部。

顶层集成TB使用原budget向量（36帧=1.5秒），真实50/100MHz与pix/48k时基，循环两轮取得≥3秒实际音频播放。SD源受1.30MB/s服务预算限制，含扇区空隙，不压缩音频时间；启动预载单列。检查无死锁、drop/expected<0.01（72帧意味着必须0丢帧），呈现帧相对音频目标差严格<1帧，实际播放的全部PCM与源一致，无underflow；不只检查done或计数。照片、WAV48/44.1、卡带及D2回归分别报告。任何失败停在当前项，不能用假模型或静默降级通过。

每步列实际文件、资源增量估计/实测状态；总LUT仍受器件剩余9081及D2已占部分约束，超过即重设计，不因D3新增而取消红线。TD实测与板测不在云端伪报。

## 适配层落实（第一步）

原页模式命令引擎对部分短于8字的突发会卡收尾；实测服务级仿真复现。适配器对逻辑1…8word统一发8word物理访问，命令首地址必须8word对齐（D2、JPEG槽和PCM都满足）；短读丢弃尾word，短写按DQM屏蔽。DQM与DATAOUT同一边沿寄存，framebuffer在ENABLE_MJPEG时才接入物理dm引脚，旧参数关闭仍为原常零掩码。测试写区后保护字不变、读R/V停顿数据保持、真实mWR_DONE/mRD_DONE后完成，实际四口调度/厂商命令模块参与仿真。

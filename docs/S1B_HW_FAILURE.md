# S1-B 板测失败报告：单拍吐字节在真实链路上破坏卡带加载

> 日期：2026-10-31　报告人：本地验证侧（ZCode）
> 分支：`feat/mjpeg@27e6d08`（S1-B）　对照：`release/RELEASE_g32_FROZEN_20261031.bit`
> 结论：**S1-B 的仿真空过，但板上失败。冻结固件正常。属 S1-B 引入的回归。**

---

## 1. 板上实测对比（同一 SD 卡、同一开关 SW7+SW5+SW6 ON、同一卡带槽）

| 遥测字段 | 冻结 g32 | S1-B | 含义 |
|---|---|---|---|
| `WC` | **25C (604)** | **000 (0)** | 卡带词数：正常 / **未加载** |
| `PC` | 014 | 000 | CPU PC：在执行 / 未启动 |
| `SP` (spr_cnt) | 1A6E (6766) | 01EF (495) | 精灵提交数：正常 / 极少 |
| `LS` | 4 | 4 | 均为"加载完成"状态 |
| `OFF` | 2A3200 | 2A3200 | 均消费 2,765,312 字节（一整块） |

**画面证据**：S1-B 下 HDMI 输出为 `video_source_test` 的彩条兜底图案（无内容源）；
冻结固件下为正常游戏画面。

**解读**：字节流在流动、总量正确（`OFF` 相同），但**解析不出任何词**（`WC=0`），
说明内容错位/损坏，而不是"没读到"。`SST` 放大是加载失败后 4 秒看门狗重试的结果，不是原因。

## 2. 仿真为什么没抓到（关键教训）

`tb/tb_sd_drain.v` 用的是**真实** `ram_dual_port_simple`（注册读 1 拍），这点是对的；
`DRAINCHK` 的 `fast_last_sector=513` 也证明单拍状态机在**该激励下**每拍吐一个字节且内容一致。

问题在**控制器行为模型**这一层：

```verilog
// tb_sd_drain.v:72-75  sd_drain_source
if (filling) begin
    if (fill_addr==511) begin filling<=0; ctrl_done<=1; end   // 写满 512 拍，同拍给 done
    else fill_addr<=fill_addr+1;
end
```

即：TB 的"SD 控制器"是**理想顺序写 + 写完立刻 done**，`ctrl_done` 与 `RD_RAM` 写入之间
只有固定的 1 拍关系。而真实链路是：

```
SPI 逐字节 → rd_sec_ram（临时区）→ 复制写入 RD_RAM（a 口）→ ctrl_done
   （sd_card_control.v:  RD_RAM 的 addra/dina/wea 接 rd_sec_ram_addr/dout/wea）
```

**`ctrl_done` 与 `RD_RAM` a 口最后写入之间的真实相位差，sim 没有建模。**
S1-B 的单拍路径比原两拍路径少了一拍隔离，正好踩在这个未建模的边界上。

### 教训（请写进设计文档的验证章节）

> **凡涉及存储器读相位的改动，测试台必须同时建模"真实控制器给出的 done 与 RAM 写入的相位关系"，
> 不能只用一个"写满即 done"的理想模型。** 真实 RAM 模型 + 理想控制器时序，仍会漏掉这类 bug。

## 3. 请排查的方向（按优先级）

1. **`ctrl_done` 与 `RD_RAM` 最后写入的真实间隔**
   在 `sd_card_control.v` 的 mode 2 路径里，`ctrl_done`（→ `ctrl_done` 输出）拉高时，
   `RD_RAM` a 口是否已经停止写入？间隔几拍？如果间隔为 0 或 1 拍，
   单拍路径首字节就可能在上一次写落定前被读出。

2. **首字节的相位**
   原两拍：`SET`(给 addr=0) → `GET`(读 data(0))。
   单拍：进入 `ST_DRAIN_GET` 后第 1 拍就读 data(0)，但同一拍 `ctrl_rd_ram_addr` 已切到 `addr+1`。
   若真实 RAM 在该拍的输出仍受"上一拍 addra"影响（尤其是复制刚结束、a/b 口同拍竞争时），
   首字节会错。请给出 b 口读与 a 口写在同拍的仲裁结论（`ram_dual_port_simple` 是写优先还是读优先、
   同址同拍的行为）。

3. **`stream_last` / 扇区边界**
   `stream_last` 依赖 `drain_addr==511 && sectors_left==1`。若首字节相位错一位，
   整个扇区的 512 字节会整体偏移，`drain_addr==511` 的判断也随之落到错误的数据上。
   请在 TB 里加一条"故意让控制器 done 比数据晚 N 拍（N=0..4）"的参数化用例，
   覆盖 N 的取值，断言字节流仍逐字节一致。

## 4. 建议的验收流程修正

原 S1-B 判据只有 `DRAINCHK`（仿真）+ 板上"三路回归"。本次暴露的缺口：
**仿真的 SD 源头模型与真实控制器不一致**。

建议改为：

- 新增 `CTRLPHASE` 用例：控制器 `ctrl_done` 相对数据晚 0/1/2/4 拍，四种相位都要过 `DRAINCHK`。
- 板测判据明确写：`WC` 必须等于镜像头部词数（`invaders` = 604 = `0x25C`），
  `PC` 必须非零且变化，`SP` 必须持续增长；仅"三路不崩"不足以验收。
- 保留 `DRAIN_1CYC=0` 的回退路径（冻结固件已证明两拍路径正常）。

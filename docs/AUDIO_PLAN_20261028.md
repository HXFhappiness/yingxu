# 映序音频方案（ES8388 + I2S + BGM）

> 状态：**方案设计，未实施**。2026-10-28 晚。
> 目标：让"多媒体平台 → 游戏机 → 计算机"这条叙事在**声音**上闭环。

---

## 0. 先纠正一个事实

板子**不是完全静音**的：HDMI 音频链路已经接好——

```
yingxu_psg ──┐
             ├─→ 音源选择 ─→ audio_arc_calculate ─→ HDMI 发送器（音频包）
I2S 输入 ────┘
```
（`design_top_wrapper.v` 第 397-470 行）

**已通**：游戏音效随 HDMI 走，显示器带喇叭就能听到。
**未接**：ES8388 模拟侧（`I2S_DO=0`、`I2S_MCLK=0`、`i2c_sclk=1`）——耳机口/板载喇叭没声音。

所以材料里"事件音效与视频同源输出"**不算虚标**，但只有 HDMI 一条路；
接上 ES8388 后，才有"独立于显示器的音频输出"，也才能做**音乐播放器**。

---

## 1. 目标链路

```
                    ┌──────────── 混音器（饱和加法，24bit 立体声）────────────┐
  PSG 音效 ─────────┤                                                        ├─→ HDMI 音频包（已有）
  BGM 音源 ─────────┤                                                        └─→ I2S 发送 ─→ ES8388 ─→ 耳机/喇叭
  （WAV / 音序器）   └────────────────────────────────────────────────────────┘        ↑
                                                                          I2C 初始化（ES8388 寄存器表）
```

要点：
- **一个混音器，两路输出**：HDMI 与 codec 拿同一份样本，天然"音视频同源"
- codec 侧需要 I2C 初始化（复用 demo 的 `ES8388_init_table.v`）

---

## 2. 时钟设计（最大技术风险点）

ES8388 作为 I2S slave，需要 FPGA 提供 MCLK：

| 信号 | 频率 | 来源 |
|---|---|---|
| MCLK | **12.288 MHz**（256×48k）| **新增一路 PLL 输出** |
| BCLK | 3.072 MHz（64×48k）| MCLK ÷ 4 |
| LRCK | 48 kHz | MCLK ÷ 256 |
| 采样 | 48 kHz / 24bit | 与 PSG 一致 ✓ |

- PSG 已经在 **pixel_clk 域**用累加器产生 48kHz 样本闸门（`INC_HZ/SAMPLE_HZ`），
  平均频率精确、抖动 1 个时钟
- 跨域：pixel_clk → MCLK 域，用**异步 FIFO**（深度 8~16 个样本足够）
  ⚠️ 上次字节 FIFO 的教训：指针必须切片索引，别让 11 位指针索引 1024 深数组

**风险与退路**
- 若 TD 的 PLL 无法精确合成 12.288MHz：改用 **11.2896MHz（44.1k）**，或让 codec 内部 PLL 容忍 ±1%
- 验证顺序：先只做"MCLK + I2S 空转 + I2C 初始化"，听底噪/测频率，再上样本

## 3. BGM 三个候选（可叠加）

### 方案 A：SD WAV 播放器（推荐，1 天）
- 复用现有 SD SPI 读 + 扇区 FIFO，输出 16bit 48k 立体声
- 带宽需求：48k × 2ch × 2B = **192 KB/s = 11.5 MB/分钟**
- 曲目：电脑端用 `tools/music2sd.py` 转换并写卡（见 §9）
- 演示价值：**菜单里选"音乐"就能放歌** → "多媒体平台"实锤
- 风险：SD 读与视频并发 → 音乐模式下不跑照片/游戏，顺序化即可

### 方案 B：硬件音序器 / chiptune（0.5–2 天，看做到什么程度）
- ROM 里存音符表（音高、时长、包络），硬件循环播放
- 优点：**不占 SD 带宽**、循环无缝、和像素风统一
- 适合：游戏内 BGM（每款游戏一首循环曲）
- 代价：作曲要用工具生成音符表（我可以写个转换脚本）

### 方案 C：CPU 驱动 APU（1 天）
- 把 PSG 从"4 个事件音"升级为 **3 方波 + 1 噪声 + 包络 + 音量**
- 由卡带 asm 直接写寄存器演奏
- 优点：强化"软件游戏自己演奏音乐"的叙事
- 缺点：作曲要在 asm 里写，适合短循环

**建议**：A（音乐播放器）+ C（游戏内音效/BGM），B 只在时间富余时做。

| 阶段 | 内容 | 工作量 | 完成标志 |
|---|---|---|---|
| **P0** | ES8388 I2C 初始化 + I2S 发送 + 混音器；PSG 同时送 HDMI 与 codec | 0.5–1 天 | 耳机口能听到游戏音效，与 HDMI 同步 |

**P0 是及格线**（兑现"音频输出"），**P1 是加分项**（多媒体平台），P2/P3 看时间。

## 9. 音乐素材：从网上下载到上板（已可用）

### 9.1 为什么要电脑端转换
MP3 解码器（Huffman + IMDCT + 子带合成）需要几千 LUT 和大量乘法器，
**FPGA 里放不下也不值得**。正确做法：PC 端转成裸 PCM，FPGA 只做播放。

**ffmpeg 已经装在 	ools/ffmpeg/**，不需要另外找转换器。

### 9.2 一条命令
`powershell
python tools\music2sd.py --in 你的歌.mp3 --slot 0 --drive E
`
自动完成：ffmpeg 转 48kHz/16bit/立体声 → 加 32 字节头 YXMA → 按固定 LBA 写卡。
其它参数：--mono 省一半空间、--rate 32000 再省一点、--list 看四个槽、
--out 文件 只生成不写卡。

### 9.3 空间账（重要）
| 格式 | 码率 | 一分钟 | 48MB 槽可放 |
|---|---|---|---|
| 48k 立体声 16bit | 192 KB/s | **11.5 MB** | **4.2 分钟** |
| 48k 单声道 16bit | 96 KB/s | 5.8 MB | 8.4 分钟 |
| 32k 单声道 16bit | 64 KB/s | 3.8 MB | 12.6 分钟 |

四个槽 = 192 MB，32GB 卡完全无压力。

### 9.4 槽布局（板子视角 LBA）
`
槽 i 基址 = 2_000_000 + i × 98_304 扇区     (i = 0..3)
物理扇区   = 基址 - 2048                    (FAT32 分区偏移)
`

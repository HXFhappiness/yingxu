## 4. 综合修复的 RTL 缺陷：sd_multi_reader `cmd_cnt` 多驱动

TD 报 `HDL-8007: net 'cmd_cnt[2]' is constantly driven from multiple places`——专用 ce 门控
计数块（板级验证过的相位逻辑）与主 FSM 的 4 处清零（复位 / S_IDLE / S_DUMMY / S_CS_UP）双重驱动。
iverilog 宽容合并不报错，仿真掩盖了问题。

**修复**：删除 FSM 侧 4 处写入，计数块独占驱动。语义等价性论证：所有进入 S_CMD/S_STOP12
的来源状态（S_IDLE / S_CS_UP / S_DUMMY）都至少完整传输 1 字节（ce 必然发生 ≥8 次），计数块
else 分支已在这些状态清零；S_FLUSH 退出链路时 cnt 恒为 0；复位由计数块承担。

**回归矩阵（tb_sd_multi，-g2005）**：

| 配置 | 结果 | 与基线对照 |
|---|---|---|
| 默认（快速引擎主路径） | **ALL PASS**（bytes_checked=14848） | 与 ms_res.txt 记录逐字一致 ✓ |
| +crcerr（注错回退） | DATA1 FAIL → 总 FAIL | **修复前副本（双驱动）结果完全相同** → 既有行为，非本次引入；该场景不在验收基线 |
| FORCE_LEGACY=1（纯原厂路径） | **ALL PASS**（15360） | 回退链路端到端完好 ✓ |
| +throttle（断流） | 未完成（仿真时间超限） | 不在验收基线；另见 §6 |

仿真编译注意：厂商 cnt.v 的参数名 `var` 是 SV 保留字、sd_write_addr.v 的不定宽拼接 operand
被 iverilog 拒绝——`tools/_sd_sim_shims.py` 生成语义等价 shim（tb/_sd_sim_shims/，厂商原文件
零改动；TD 综合仍用原文件）。

## 5. 时序（gate.timing，慢角）

| 指标 | 旧构建 wt_d41 | 新综合 yt_s81 |
|---|---|---|
| WNS | -7.804 ns | **-3.116 ns** |
| TNS | -1.6230 μs | **-0.1623 μs** |
| 违例端点 | 805 | 153 |

最差路径（73.33 MHz CPU 域，PLL clkc[1] 周期 13.643 ns）：

```
pc_r_reg[3].q ─ pc_out(yx8_cpu.v:52) ─ flag 逻辑(:339) ─ sh[0](:154)
  ─ ADD16 add0/add1(:156-157) ─ flag_z 组合链（13 级，数据 16.643 ns）
  → flag_z_reg.d      Slack = -3.116 ns（预算 13.643 ns）
```

这正是 YX-8.1 计划预判并明确处置的情形："若 16 位组合路径不收敛，先报告关键路径，
不擅自改成多拍或烧录"。要点：

- 域为 CPU 73.33 MHz；违例含义是该域慢角上限约 59.6 MHz。
- 旧构建（同为 YX-8.1，含残留负载）同域违例更深（-7.8 ns）且板级实测正常，慢角报表偏悲观；
  本轮按计划不改 RTL，路径已定位（如需收敛，ADD16 旗标链拆多拍是独立任务）。
- SD/视频域的跨域路径在 Clock Summary 中标注 CC-From/CC-To，SDC 仅约束 50 MHz 主时钟。

## 6. 遗留

- `+throttle` 断流场景：仿真时间超限未跑完（断流使 8KB 读取的仿真墙钟 >7 分钟），
  不在验收基线；后续如需可拆段跑或加大 maxms。
- 顶层 io 报告中 `hardware_test_P0_UART_V5_CRC32.v` 有两个未驱动网络告警
  （cart_ready_w / lba_rom，:142/:351）与 YX-8.1 无关，属测试壳既有告警。
- 综合工程快照 `out/yt_s81/src` 为源码树副本，下次综合前需重新同步（本次已踩过不同步的坑）。

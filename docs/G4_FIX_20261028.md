# G4 修复记录 — 2026-10-28 凌晨：移位判官变绿，卡带全通

> 接续 `STATUS_20261027_NIGHT.md` 的 P0（移位疑似板上失效）与 P1。
> 本日结论：**不是移位器问题，是三个管线/存储器 bug 的叠加**。全部修复，仿真四卡带全绿。

## 排查路径（关键决策点）

1. 三方对齐排除"旧判官"：本地重汇编 dbg_shift = 包内 .yxc = 卡上内容（MD5 一致）。
2. Python 模拟器跑判官：**绿**（R0=16，写 0x07E0）——判官程序本身正确。
3. **SOC 级仿真复现红色**（tb_burst + dbg_shift，SPRITE c=ff0000）——不是综合差异，
   是 RTL 真实 bug，模拟器没建模到。此后全程本地调试，不再烧一圈猜一次。
4. COSIM 逐指令退休轨迹：SHLI 正确（R0=10），SHRI 得 0x04 = 0x10>>2 ——
   **它移的是上一条指令的结果**。锁死"寄存器写回时序"。
5. 逐拍内部轨迹（state/ir/we/wb/R0）抓到现行（CYC 8-11）。

## 三个根因与修复

### ① 寄存器写回不看状态机（主凶）
S_WAIT 等待拍里取指已就位、ALU 组合逻辑一直在算，`we_regs` 在等待拍就把
**下一条指令**的结果提前写进寄存器堆；执行拍再算一次时操作数已被污染。
→ **所有非幂等 ALU 指令板上双执行**：移位×2、ADDI +2、INC +2。
selftest 全绿是因为它只用幂等指令（MOVI/STR/LDR/CMPI/分支）。
修复：`yx8_cpu.v` 写回加 `exec_cyc = (state==S_RUN)||(state==S_F2)` 门控
（寄存器堆 + 标志一起门控）。

### ② 复位后首条 JSR 的 F2 重读第一字
复位期 `next_pc = rst ? entry : npc` 把取指地址钉死在 entry；CPU 释放后第一条
S_RUN 时 `raddr_q` 仍是 entry，F2 拍 instr = ram[entry]（第一字自己）→
npc = {A, lo} = 0x0A0A → 掩码 0x20A，跳进 NOP 区。pong 当时是**碰巧**被 NOP 雪橇
绕回 pc=0 自愈的；snake 撞上 ③ 的 JMP 陷阱永远出不来。
修复：`yx8_cpu.v` JMP/JSR 改为 S_RUN → **S_WAIT** → S_F2 → S_WAIT → S_RUN
（`jmp_r` 标志分流），第二字必定走完两拍取指。JMP/JSR 从 2 拍变 3 拍，无感。

### ③ 元数据字是可执行地雷 + 尾字路径跳过填充
- 元数据字 {daddr, dlen[15:8], dlen[7:0]} 的 **op = daddr**：snake 的 daddr=0x50
  恰好 = JMP 操作码。NOP 雪橇走到 0x3FF 撞上它被弹回 0x200，永远回不到程序。
  修复：编码改 **{8'h00, daddr, dlen[7:0]}**（op=NOP；dlen≤224 八位足够），
  解包 FSM 同步改解析（addr=[15:8], len=[7:0]）。
- L_DATA 尾字路径（dlen 非 3 倍数）直接跳 L_DONE，**L_FILL 从未执行**——
  snake 的程序区外全是未定义内容。修复：三条完成路径统一进 L_FILL；
  L_FILL 改两段式（[代码尾..767] + [数据区后..1022]，跳过数据打包区，
  **不再覆盖 1023**——元数据必须留给解包 FSM 读）。

### ④ SW6 换槽不触发精灵表擦除（当晚追加）
SW6 在卡带模式里只切换 LBA，`game_sel2` 恒为 2'd2——wrapper 的擦除逻辑盯的是
game_sel2 变化，所以换槽永不擦表。invaders→breakout 换槽后，invaders 最后一帧
的外星人永久残留在精灵表里（实测截图 snap16：外星人叠在 breakout 砖块上）。
修复：`yx8_cart_soc.v` 在 loaded_p 下降沿（重载开始）主动发 16 个 en=0 提交，
扫清整个精灵表（`wipe_act/wipe_cnt`，置于 I/O 块尾，后写覆盖）。
板上验证：invaders→breakout 换槽零残像（snap17/18），invaders 编队推进+击落正常。

## 附带修复（同一门控缺失的连带伤害）
- SOC 访存副作用加 `cpu_retire` 门控：精灵提交不再双发（spr_commits 2→1）、
  LFSR 读不再双步进（RAND 与模拟器确定性一致）。

## 当晚插曲：SD 热插拔后"全灭"（非 bug）

换卡写卡带后未重新上电 → SD 初始化只在上电瞬间执行一次 → LED0 灭、
彩条/黑屏、两个卡带都"死"。重新插紧卡 + **断电重上** 即恢复。
ROM 自检（SW0）用于隔离：CPU/显示路径完好 → 排查方向立即收敛到 SD/加载。

**演示日规程**：写卡带一次性完成，卡留在板内不再拔；任何换卡/插拔后必须断电重上电。

## 教训（补进方法论 §8）

- **模拟器（yxem）≠ RTL 仿真**：本次 bug 恰好藏在模拟器不建模的时序层。
  回归三件套 = yxem 语义 + SOC 仿真 + 板级判官，缺一不可。
- SOC 仿真里"程序区外内容"必须可复现：L_FILL 是正确性的一部分，不是优化。
- 逐拍内部轨迹（state/ir/we/wb/regs）是定位此类 bug 的最快路径，
  `_mktrace2.py` 生成的 tb_sh_cyc.v 可复用。

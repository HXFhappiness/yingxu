### 2.2 WAV 播放器（`yingxu_wav_player.v`，新模块 ~340 行）
- **SD 分块拉取**（探针零改动）：探针每 restart 读 5401 扇区(2.76MB)后停；
  播放器每次取 8 扇区(4KB=1024 立体声样本)恰满 FIFO，降到低水位(256)再取下一块；
  基址递增 `MUSIC_BASE(2,000,000) + chunk*2,765,312`，一拍 `wav_restart`，
  顶层 mux 进探针 start_sector
- YXMA 头解析（'YXMA'|ch|rate|frames|pcm_bytes）；mono 复制到 L/R；任意 rate 分数消费
- 异步 FIFO：`ram_dual_port_simple` 模板 32bit×1024（sys 写/pix 读），
  **指针格雷码跨域**（rgray/wgray 双向 + 2FF + 反格雷）
- 输出：PSG 的 48kHz valid 作为弹出节拍（与 PSG 天然对齐），16bit→24bit ×128（-6dB 混音余量）
- 断流看门狗：任意状态 3.3ms 无字节 → 重发当前块请求（修"restart 被吞=永久静音"）

### 2.3 硬件集成

## 3. 当前挂起的问题（接手第一优先）

### 3.1 全 OFF（照片模式）不出图 + 采集卡抓帧挂起
- 现象：断电重上后全 OFF，用户报"看不到图像"；抓帧命令挂死（dshow 等帧不来
  = 强烈暗示**板子无 HDMI 信号**）；采集卡音频端点单独打开也拿不到样本（需视频同开）
- g9 时序报告健康（HWNS +0.022 / SWNS -0.566，与历次正常构建一致）→ 不是静态时序
- 排查顺序：
  1. **看显示器**：黑+无信号？纯黑？品红（SD 失败指示）？LED0 亮否？
  2. **烧回退点** `out/bitstream_backup/build54_scale.bit` → 视频恢复 = g9 位流问题；
     仍无视频 = 板子/连线问题
  3. 若 g9 有问题 → 二分：先摘掉 wav player 实例（wrapper 注释掉）只留端口 →
     构建烧写看视频；再定位到具体子结构
- 嫌疑点（未证实）：wav player 的 pix 域新逻辑对像素时钟的动态影响；
  或 ram_dual_port_simple 32bit×1024 双时钟实例的布局/布线问题（时序虽过，
  但 PLL/HDMI 物理路径可能被挤压——TD 报告看不出这类问题）

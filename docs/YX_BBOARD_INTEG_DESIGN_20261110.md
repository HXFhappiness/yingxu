  不进本轮仿真范围（初赛已结束，仿真全过即验收）。
- EG_PHY_PLL shim 频率/相位公式已按 Sdram_PLL/HDMI 两个 wrapper 交叉验证（见 shim 头注释）。

## 2. 数据流与端口分配

```
A板字节流(YXV2) → yx_vp_ixdec → yx_vp_ixbuf → yx_vp_band(深度2握手+扫描读口)
                                                    │ scan_ra/scan_rd
                                                    ▼
                              扫描端(新) ──WR1──> vendor SDRAM 控制器 <──RD1── 显示消费端(行为)
                              按"带"整块入帧       100MHz            按带连续流读出
```

- WR1 = 扫描入帧（band 行缓冲半区 → SDRAM 帧缓冲）
- RD1 = 显示读出（帧缓冲 → 行为消费端；连续流 + afull 自动节流）
- WR2/RD2 闲置（接地）
- 帧缓冲布局：band-major 线性——带 b 的 4 行×1280 像素 = 5120 字(16bit) = 2560 字(32bit)
  存于 [b*2560, (b+1)*2560)；**5120(16b)=20 页(256字/页) 页对齐** ✓
  720p 全帧 180 带 × 2560 = 460800 字 < 2M ✓

## 3. 扫描端节奏分析（不欠扫描论证）

| 量 | 数值（720p，100MHz） |
|---|---|
| 渲染 1 带 | 320 块 × ~20 clk ≈ **6600 clk** |
| 扫描 1 带入帧 | 20 页 × (LOAD 1 + 推 256 + 突发尾) ≈ **5500 clk**（推数与排空重叠） |
| 握手深度 | band 深度 2（本设计已实现）：渲染领先 ≤2 带 |
| 结论 | 扫描速率(5500) < 渲染速率(6600) → 扫描端恒领先；深度 2 保证行缓冲半区读写不冲突 → **不欠扫描** |

安全边界：扫描端比渲染端快 ~17%，即使 SDRAM 刷新停摆（每 103µs 约 10 拍）也吃掉余量绰绰有余。

## 4. vendor 控制器使用契约（sanity 实测固化）

1. **页模式（SC_PM=1）**：每突发 1 条 READ/WRITE 命令 + 全页流式收发 →
   **单次突发长度 ≤ 256 且不得跨 256 字页边界**（否则 SDRAM 页内回卷 → 错数据）。
   扫描端按页（256 字）对齐分段 LOAD。
2. **写端口**：LOAD(addr,len) 后推数，**FIFO 占用 > AE(127) 才起突发**（<128 字永不触发）；
   推数 1 字/拍与排空同速 → 不欠载。地址按 rWR1_LENGTH 递增，MAX_ADDR 区内回卷。
3. **读端口**：连续流——RD FIFO 未近满（AF=128）就不断起突发；读回数据是
   [RD1_ADDR, RD1_MAX_ADDR) 区间的**循环序列**（帧缓冲回卷语义正好匹配显示刷新）。
4. **FIFO do 语义**：re 采样沿寄存（do 在 re 后一拍可见）——消费者协议：
   `re 一拍 → 下一拍读 do`。sanity TB 已按此协议验证。
5. **控制器 CLK 由内部 PLL 生成**（clk0），TB/上层**不得驱动 CLK**；extlock 后等
   INIT_PER=24000 clk 初始化完成再使用。
6. 长度字段 [8:0] ≤511；本设计一律用 256（页对齐）。

## 5. 集成 TB（实现③）判定

- A→B 源：行为字节流发生器按 ixbuf 的 accept 握手推 YXV2 流（复用 ixpipe TB 的流加载方式）。
- 不欠扫描断言：**扫描端 band ack 节拍 ≥ 渲染 band_done 节拍**（渲染永不因 pend_cnt==2
  停等超过阈值拍数）；显示消费端按 4 行节拍回 ack（真实扫描时序替代）。
- 对拍：扫描端写入 SDRAM 模型的数据 与 band 行缓冲对应带逐字一致（采样比对）。
- 验收几何：720p（W=1280 H=720 CBSIZE=1024）复用 vp_720_5f.yxv2 + ref 数据。

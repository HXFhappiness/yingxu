# 映序主色板 YX-256

> 版本 v1.0 · 适用：YX-8 卡带游戏（EG4S20 / HDMI 1280×720）
> 生成工具：[tools/palette.py](../tools/palette.py) · 完整色表：[PALETTE_TABLE.md](PALETTE_TABLE.md)

---

## 0. 一句话

**游戏美术只用 256 个色号（索引）说话；每个色号对应一个 16 位 RGB565 值，由 `tools/palette.py` 唯一定义。**
美术交 8bpp 索引图，程序把索引翻成 RGB565 写进精灵寄存器——两边永远对得上。

---

## 1. 为什么要先定色板

1. **硬件是 RGB565**，不是 24 位。任意 `#RRGGBB` 上屏都会被量化，同一个"看起来一样"的颜色在不同游戏里会变成不同值 —— 必须有一个权威表。
2. 卡带的 `.data` 段只有 **224 字节**，塞不下 512 字节的整表。所以每款游戏只内嵌自己用的 **子色板**（4~32 色）；索引号在全局唯一，才能让"美术图 → 程序常量 → 屏幕"三者可对齐。
3. 后续如果加"图案精灵/瓦片 ROM"（见 §10），索引色板是其天然的数据格式，现在定下来不用返工。

---

## 2. 硬件事实（美术和程序都必须知道）

| 项目 | 现状 | 对美术的含义 |
|---|---|---|
| 精灵颜色寄存器 | `0xEF SCL`（低字节）+ `0xF0 SCH`（高字节）= **RGB565** | 只能从色板里取色，不要直接用照片里的颜色 |
| 精灵数量 | **16 槽**（槽 0..15） | 一帧最多 16 个矩形；"一个角色"通常占 1 槽 |
| 精灵形状 | **实心矩形**（w×h 单色） | 现阶段没有逐像素图案；造型靠多个矩形叠 + 配色 |
| 砖块层 | 60 格（10 列 × 6 行，每格 128×32 px） | 打砖块类可直接用，颜色由游戏逻辑逐格点亮 |
| 背景瓦片层 | 40×24 瓦片，**程序化生成**（星野等），RGB888 | 目前不读美术图；将来可改为从卡带加载地图 |
| 分辨率 | 1280×720 | 精灵坐标是像素坐标（0..1279 / 0..719） |

> ⚠️ **字节顺序**：先写 `SCL` 再写 `SCH`，否则会闪一帧错色。
> 颜色值 = `SCH<<8 | SCL`，即 `R[15:11] G[10:5] B[4:0]`。

## 3. 索引布局（256 色）

| 区间 | 数量 | 内容 | 名称前缀 |
|---|---|---|---|
| `0x00`–`0x0F` | 16 | 灰阶（黑→白，16 级） | `YX_GRAY_0..15` |
| `0x10`–`0x1F` | 16 | 基础/纯色（红绿蓝青品黄…） | `YX_RED` 等 |
| `0x20`–`0x9F` | 128 | **16 个色系 × 8 级明暗**（主用区） | `YX_<色系>_1..8` |
| `0xA0`–`0xBF` | 32 | 4 个材质系 × 8 级（皮肤/木/金属/石） | `YX_SKIN_1..8` |
| `0xC0`–`0xDF` | 32 | 8 个霓虹系 × 4 级（发光/科幻） | `YX_NEON_*_1..4` |
| `0xE0`–`0xEF` | 16 | UI 语义色（底/面板/文字/强调/警告…） | `YX_UI_*` |
| `0xF0`–`0xFE` | 15 | **保留，禁止使用** | `YX_RESERVED` |
| `0xFF` | 1 | **透明/跳过标记**（不是颜色） | `YX_TRANSPARENT` |

## 7. 使用规则（硬约束）

1. **只用 0x00–0xEF**；`0xF0`–`0xFE` 保留；`0xFF` 只作为图片里的透明标记。
2. **每款游戏自报子色板**：在 `cartridges/<game>.asm` 顶部列出自用色号（≤100 色），并在 `.data` 里只放这些色的 RGB565 表。程序里不得出现裸颜色值。
3. **同一物体固定一组 ramp**：例如"砖块行 1"用 `YX_VERMILION_3..5`，不要混色系。
4. **暗色不要用纯黑压边**：用 `YX_GRAY_2..4` 的同色系暗部（`_1`/`_2`），观感更统一。
5. **对比度检查**：文字/关键物体与底色至少差 5 个灰阶（`YX_GRAY_*` 相差 ≥5）或亮度差 ≥40%。
6. 精灵色一次只能用一种；需要"描边"就多占一个槽（或增大矩形 + 后面的层遮挡）。

## 9. 美术交付流程

### 9.1 作图规格

- 格式：**8bpp 索引 BMP**（Photoshop/GIMP/Aseprite 导出"索引色"，调色板前 N 项必须等于主色板前 N 项，或直接在文件里写入主色板）
- 透明：涂成 `0xFF`
- 尺寸：单个精灵 ≤ 128×128；建议 16×16 / 24×16 / 32×32
- 对齐：按 8 像素网格作图（坐标×8 换算最省指令）

### 9.2 三条命令

```bash
# 1) 查色号（给了 RGB，问该用哪个索引）
python tools/palette.py --nearest "3F7FBF"

# 2) 校验美术图（索引是否都在色板内、颜色是否一致）
python tools/palette.py --check art/alien.bmp

# 3) 转成矩形列表（当前引擎：每帧 ≤16 个矩形）
python tools/palette.py --emit-rects art/alien.bmp > out/alien_rects.inc
```

### 9.3 生成程序常量

```bash
python tools/palette.py --asm out/palette.inc     # 256 色全表（512B，仅调试用）
python tools/palette.py --table                   # 人类可读全表
python tools/palette.py --markdown > docs/PALETTE_TABLE.md
```

## 10. 当前限制与路线图

**限制（v1.0 现实）**：精灵是实心矩形，无法画逐像素图案。所以：
- 外星人/砖块"造型"靠：多个矩形组合（≤16 槽）、砖块 60 格、配色对比。
- 真正的像素画（8×8 字符 ROM + 调色板查表）需要改硬件：

**路线图 R1（建议下一个硬件迭代做）**
1. `yingxu_sprite_engine` 增加"图案模式"：每个精灵多一个 `pattern_id`，图案存 BRAM（例如 64 个 16×16 的 8bpp 图案 = 16KB）。
2. 卡带头扩展：`pattern_count` + 图案数据段（8bpp 索引，逐行打包）。
3. 调色板：卡带加载时把子色板写进 16×RGB565 的调色板寄存器（`0x50`–`0x6F` 之类的 I/O 窗口），图案像素 = 索引查表。
4. 这样美术就能直接交 8bpp 索引图，`palette.py` 现有工具链不用改。

## 11. 提交检查清单（美术自检）

- [ ] 图是 8bpp 索引模式，不是 RGB
- [ ] 所有索引 ≤ `0xEF`（不含保留区）
- [ ] 透明区域标记为 `0xFF`
- [ ] `python tools/palette.py --check <file>` 输出 `OK`
- [ ] 附一份"用色清单"（哪些色号，各用于什么）
- [ ] 单帧矩形数 ≤ 16（`--emit-rects` 会打印数量）
- [ ] 与底色的对比度足够（暗背景上不要用 `_1`/`_2` 暗部做主体）

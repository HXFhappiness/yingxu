# 映序卡带头格式规范（YXC v1 / v2）

> 状态：草案。v1 为**已实现**格式（依据 `yx8_cart_soc.v` 解析器与 `yxem.py` 实现）；
> v2 为提议扩展，向下兼容 v1。
> 目的：让卡带不仅"带程序"，而是"声明它需要一台什么样的机器"。

---

## 1. 文件结构

```
+----------------+  0x00
|  头部 32 B     |
+----------------+  0x20
|  代码段        |  3 B/字 × code_words
+----------------+
|  数据段        |  data_len 字节
+----------------+
|  [扩展块]      |  v2 可选，由 ext_off 指向
+----------------+
```

- 代码段：每条指令 3 字节，小端拼装为 24 位字。
- 数据段：原样装进数据 RAM，起始地址 `data_addr`。

---

## 2. 头部字段（v1，32 字节）

| 偏移 | 长度 | 字段 | 约束 |
|---|---|---|---|
| 0x00 | 4 | `magic` = `'YXCA'`（0x59584341） | 必须匹配，否则装载器终止 |
| 0x04 | 1 | `ver` | 当前 0x01 |
| 0x05 | 1 | `flags` | v1 未使用，v2 定义为能力位图 |
| 0x06 | 2 | `entry`（LE） | 程序入口字地址 |
| 0x08 | 2 | `code_words`（LE） | **1 ≤ code_words ≤ 768** |
| 0x0A | 2 | `data_len`（LE） | **≤ 224** |
| 0x0C | 1 | `data_addr` | **< 0xE0**，且 `data_addr + data_len ≤ 0xE0` |
| 0x0D | 3 | 保留 | v2 定义为 `ext_off`（24 位，小端） |
| 0x10 | 16 | `title` | ASCII，不足补 0，仅用于工具链显示 |

**硬件校验规则**（`yx8_cart_soc.v` 实测）：
`code_words == 0 || code_words > 768 || data_addr >= 0xE0 || data_len > 224 ||
 data_addr + data_len > 0xE0` → 装载失败，进入 `L_DONE`。

---

## 3. 装载流程（平台侧）

1. 从 SD 卡固定 LBA 读入头部，校验 `magic` 与字段约束；
2. 代码段 3 字节/字写入程序 RAM 0x000–0x2FF；
3. 数据段写入程序 RAM 0x300–0x3FE（数据镜像区）；
4. 描述符 `{data_addr, data_len}` 写入程序 RAM[1023]；
5. 置 `loaded`，CPU 从 `entry` 启动；数据镜像由 SoC 搬到数据 RAM。

**卡带视角**：启动时数据段已在 `data_addr` 处就绪，无需自己加载。

---

## 4. v2 扩展：能力位与平台协商

### 4.1 `flags`（偏移 0x05）定义为能力位图

| 位 | 名称 | 含义 | 缺失时 |
|---|---|---|---|
| 0 | `CAP_SPRITE` | 需要精灵引擎。**注意与 v1 工具的兼容**：`yxa.py` 在 v1 卡带里用 bit0 表示"有 DATA 段"，平台对 `flags` 为 0/1 的 v1 卡带不做能力检查，故不冲突 | 拒绝启动 |
| 1 | `CAP_PSG` | 需要音效 | 静音运行（可降级） |
| 2 | `CAP_INPUT` | 需要按键 | 拒绝启动 |
| 3 | `CAP_FRAME` | 需要帧计数/vblank | 拒绝启动 |
| 4 | `CAP_BRICK` | 需要砖块层 | 拒绝启动 |
| 5 | `CAP_PAD` | 需要 PS2 手柄（12 键 + 双摇杆，I/O 0xF7–0xFC） | 降级为 2 键运行 |
| 6 | `CAP_EXT` | 需要扩展总线（板间链路，以太网承载） | 降级为单板运行 |
| 7 | `CAP_YX81` | 需要 YX-8.1 的 16 位寄存器对指令（0x60–0x68）；平台在 `0xFD CAPS` bit0 上报该能力 | 拒绝启动（装载器于头部校验时终止，LED1 常亮） |

**兼容规则**：`flags == 0` 视为 v1 卡带，平台**不做能力检查**，按全部可用处理。
`yxa.py --isa yx81` 会把 bit7 与 bit0（有 DATA）一起写入。

### 4.2 `ext_off`（偏移 0x0D–0x0F）

24 位小端，指向文件内的扩展块；`0` 表示无扩展块。

扩展块建议格式（v2.0，每项 4 字节）：

| 字段 | 长度 | 说明 |
|---|---|---|
| `tag` | 1 | 0x01 = 平台配置；0x02 = 图标；0x03 = 说明文本 |
| `len` | 1 | 本项后续字节数 |
| `data` | len | 内容 |

示例——平台配置项（tag=0x01）：
`sprites_used`（1 B，0–16）、`preferred_fps`（1 B）、`reserved`（2 B）。

### 4.3 平台行为

装载器解析 `flags` → 与平台能力表比对：

- 全部满足 → 正常启动；
- 存在"可降级"缺失（`CAP_PSG`/`CAP_EXT`）→ 置降级标志后启动；
- 存在"必需"缺失 → 不启动，在 `SCORE` 口显示错误码 `0xE0 | 缺失位号`，LED 同步指示。

---

## 5. 兼容性矩阵

| 卡带 | 平台 v1 | 平台 v2 |
|---|---|---|
| v1（flags=0） | 正常运行 | 正常运行（不做能力检查） |
| v2（flags≠0） | 能力位被忽略，按 v1 运行（作者需自行保证不越界） | 按第 4.3 节协商 |
| v2 + ext_off≠0 | 扩展块被忽略 | 解析扩展块 |

## 6. 工具链对应

| 环节 | 工具 | 说明 |
|---|---|---|
| 汇编 + 打包 | `tools/yxa.py` | 生成头部与代码段，写入 `title` |
| 指令级模拟 | `tools/yxem.py` | 解析同一份格式，作为硬件参照实现 |
| 写卡 | `tools/write_cart.py` | 按固定 LBA 写入 SD 卡 |
| 硬件装载 | `yx8_cart_soc.v` | 校验字段、装填程序/数据、启动 CPU |

**新增 v2 字段时，四处必须同步**：`yxa.py`（生成）、`yxem.py`（解析）、`yx8_cart_soc.v`（校验）、本文档。

## 7. 待决定项

   平台参数 `ENABLE_YX81=0` 时声明 bit7 的卡带拒绝启动；其余能力位仍未协商（约 20 行的扩展点保留）。
2. 扩展块放在文件末尾会拉长卡带的最小读取长度；若卡带接近槽位上限，应改用"扩展块置于头部之后、代码之前"的方案。
3. 是否需要为卡带保留一个 16 位校验字段（当前依赖 SD 层无校验，损坏只能在仿真阶段发现）。
